# 海外保险数字化平台 — 险种字典维护与管理 需求说明书

**文档版本：** V1.0.5  **创建日期：** 2026-09-24  **文档状态：** 评审稿
**关联文档：** PRD《产品PRD/V1.0.2-险种字典-20260924.md》｜ 接口文档《技术方案/V1.0.0-系统集成接口文档-20260917.md》

## 1. 背景与问题

系统在三个位置硬编码维护同一份「业务线 → 子险种」联动字典，承保范围列表亦在前后端多处硬编码：

| 位置 | 内容 | 问题 |
| --- | --- | --- |
| 后端 `carrier-service/integration.service.ts` | SUB_LINE_MAP（11 组业务线×子险种）、COVERAGE_ALIASES 归一化表 | 与前端副本靠注释约定人工同步 |
| 前端 `web-carrier-admin/ProductForm.tsx` | SUB_LINE_MAP 副本、COVERAGE_KEYS 9 项、历史数据别名回填表 | 与后端副本人工同步 |
| 联调模拟器 `web-carrier-admin/public/workos-simulator.html` | SUB_LINE_MAP 副本（含旧险种兼容键） | 第三份副本 |

核心问题：

| 编号 | 问题 | 影响 |
| --- | --- | --- |
| P1 | 三份副本人工同步，一致性风险高（历史已出现大小写漂移：`Flat`/`ageband`） | 建品表单、集成匹配、模拟器三处口径可能不一致 |
| P2 | 新增/调整险种需改 3 处代码、前后端两次发版 | 变更成本高、周期长 |
| P3 | 承保范围全局 9 项，不随业务线联动（Home 业务线下仍显示 Collision），集成匹配不按业务线校验 coverages | 录入与校验口径过宽 |
| P4 | 无启停、排序、中英名称维护、引用影响分析与操作审计 | 无管理能力 |

## 2. 业务目标

1. 字典数据入库，提供统一管理界面，实现「一次维护、处处生效」。
2. 实现真正的三级联动：业务线 → 子险种、业务线 → 适用承保范围。
3. 建品表单、集成匹配校验（I3 consultation/match）、联调模拟器三个消费方全部改为动态读取，消除硬编码副本。

## 3. 用户与场景

| 角色 | 场景 |
| --- | --- |
| 系统管理员 | 新增业务线/子险种、维护中英文名称、调整排序、停用过时险种、勾选各业务线适用承保范围 |
| 产品管理员 | 建品时按业务线联动选择子险种、勾选承保范围（仅见该业务线适用项） |
| 外部系统（workOS 等） | 通过集成接口获取字典快照，用于入参校验前置提示 |
| 实施联调人员 | 模拟器下拉与生产字典实时一致，无需升级模拟器 |

## 4. 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-1 | 业务线管理：新增/编辑/删除、中英文名称、排序、启用停用 | 高 | 名称中英必填；code 创建后不可改；删除被产品引用项时拒绝并提示引用数量 |
| FR-2 | 子险种管理：挂在业务线下维护，支持排序、启停 | 高 | 在所属业务线下维护；同业务线下 code 唯一 |
| FR-3 | 承保范围管理：全局维护，中英文名称、排序、启停 | 高 | code（camelCase 稳定 key）创建后不可改 |
| FR-4 | 业务线×承保范围关联：为每个业务线勾选适用承保范围 | 高 | 建品表单按业务线过滤；集成 match 对不在适用范围的 coverages 给出明确错误码；迁移时每个业务线默认关联全部现有 9 项（行为兼容） |
| FR-5 | 统一查询接口：登录态三级联动树接口 + 集成侧字典快照接口（签名鉴权、含 version） | 高 | ProductForm/模拟器改读接口后无本地字典副本 |
| FR-6 | 引用影响提示：停用/删除前展示关联产品数（按 line_of_business/sub_line/coverages 统计） | 中 | 提示数量准确 |
| FR-7 | 操作审计：字典增删改、启停、关联变更记审计（操作人/时间/变更前后值） | 中 | 复用现有 audit.service，可在审计查询中检索 |
| FR-8 | 存量数据播种：迁移 SQL 建表并播种现有 11 组业务线×子险种、9 项承保范围、全量业务线×承保范围关联 | 高 | 播种后现有产品数据正常回显、match 行为不变 |
| FR-9 | 消费方改造：ProductForm、integration match 校验、模拟器全部改读字典 | 高 | 三处硬编码副本删除；match 既有错误码语义不变 |

## 5. 非功能需求

- **权限**：字典管理仅超级管理员/系统管理员角色可见，沿用现有权限点机制。
- **性能**：字典读多写少；管理端保存后进程内缓存立即失效；字典查询接口 P95 < 100ms。
- **i18n**：名称双语入库（name_zh/name_en），界面按当前语言展示；i18n 文件中 9 个 coverage 标签保留为兜底。
- **兼容**：历史产品数据（PascalCase 别名）回显不受影响，现有归一化逻辑保留为只读兜底层。

## 6. 约束与边界

- 集成接口 I1–I3 对外契约（路径、请求/响应结构、错误码取值）不变，仅数据源内部化。
- 字典项 `code` 不可变；删除仅限未被引用项；停用为常规下线手段。
- 费率因子（FACTOR_KEYS）字典化不在本期范围，列为二期候选。

## 7. 已确认决策

1. 承保范围实现真三级联动（新增业务线↔承保范围关联表）。
2. 管理页面挂在「系统管理」菜单下。

## 8. 成功指标

1. 全库检索不再存在 SUB_LINE_MAP 硬编码副本（消费方均改读接口/缓存）。
2. 新增一条子险种字典无需发布任何代码，5 分钟内三个消费方全部可见。
3. 建品表单承保范围选项随业务线联动过滤，集成 match 校验口径与表单一致。
