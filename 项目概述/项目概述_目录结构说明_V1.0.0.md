- `产品功能清单_V1.0.0.md` 是面向开发的逐条功能拆解（字段级定义）
- `海外保险数字化平台_保险公司管理与渠道管理_需求文档 V1.0.0.md` 是对外简化版（适合外部合作商阅读）

### ❓ Q: Figma 原型与正式代码的关系？
**A**: 
- Figma Make 原型（`产品设计/UI-V1.0/`）是**纯前端演示项目**，使用 Mock 数据，独立于正式代码仓
- 正式代码（`insurance-platform`）需要对接真实数据库和 NestJS 后端服务
- 开发顺序：**先完成 Figma 原型 UI 还原** → **再逐步替换为真实 API 调用**（通过 `auth-api-client.ts`）

### ❓ Q: 为什么使用 React 19 + NestJS 10 而非 Next.js？
**A**: 
- 采用 **前后端分离架构**：前端独立部署（Vite SSR 可选），后端微服务化（NestJS）
- Next.js 的 SSR/SSG 特性并非本项目必需，React SPA + Vite 更轻量、更易维护
- NestJS 提供更强的 TypeScript 支持、依赖注入、模块化能力，适合复杂企业级应用

### ❓ Q: 如何查找某个具体功能点的实现？
**A**: 
1. 在 `产品功能清单_V1.0.0.md` 中搜索功能 ID（如 "1.2.5"）
2. 找到对应的 UI 原型页面路径（如 "/products/create"）
3. 在 `insurance-platform/apps/web-carrier-admin/src/views/` 下查找同名 TSX 文件
4. 相关的领域逻辑通常在 `services/` 或 `packages/` 子目录

## 七、总结

本项目的文档与代码组织结构清晰分离：
- **文档层**（Markdown 文件夹）：存储需求、设计、计划、测试等静态知识资产
- **设计层**（`UI-V1.0/`）：Figma Make 驱动的纯前端原型项目
- **代码层**（`insurance-platform/`）：Monorepo 架构的微服务系统

这种分层结构使得：
✅ 产品经理可以专注于需求文档，无需触碰代码  
✅ 前端开发者可以先完成 UI 还原，降低对后端的依赖  
✅ 后端工程师可以并行开发 API 服务，不受 UI 细节干扰  
✅ QA 测试人员可以根据功能清单编写自动化测试用例  

所有文档遵循版本号管理规范，便于追溯历史变更与团队协作。
