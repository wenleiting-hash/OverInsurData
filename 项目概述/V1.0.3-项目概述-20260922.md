## 一、项目定位与业务架构

### 1.1 业务定位

本平台定位于**美国保险市场的中间平台**（MGA / 聚合平台模式），核心价值链路为：

```
保险公司（上游） → 我司（平台方） → 渠道合作商（下游） → 终端客户
```

**三方关系明确：**

| 关系层级 | 方向 | 核心内容 |
|---|---|---|
| 上游合作 | 我司 ↔ 保险公司 | 签约、合同、结算参数、对接人、续约直接登记、合作协议产品关联 |
| 中间授权 | 保险公司产品 → 我司 → 渠道 | 产品授权（6 开关 + 限额继承）、前置校验三件套（产品可售州 ∩ 渠道持牌州 ∩ 合作协议有效期） |
| 下游管理 | 我司 ↔ 渠道 | 档案、层级、合作、佣金、培训、合规硬联动、政策单向下发 |
| 终端交付 | 渠道 → 终端客户 | 渠道商上报客户询价、报价确认、投保申请、出单、批改、续保、退保、理赔（渠道订单本期建设，从询价 Quote 起步，6 种订单类型） |

> **说明：** 保险公司管理为我方纯内部管理域，上游保司均未开放 API，数据靠人工录入/文件导入，全域不设审批流（登记制 + 审计日志）；V1.0.3 新增 workOS 集成（SSO + 业务环节只读接口），详见《V1.0.3-系统集成-20260917.md》。

### 1.2 业务国别分轨（V1.0.3 新增）

| 维度 | US（美国业务） | CN（国内业务，预留） |
|---|---|---|
| 监管口径 | NAIC / 各州保险监管局、NIPR、State DOI | 中国银保监口径（预留） |
| 业务员资质 | Individual Producer、NPN、License States、License LOA、Appointment（Carrier × State）、CE 学时 | （预留扩展点） |
| 佣金类型 | 直接佣金、Override、续期、Contingent Commission、MGA 管理费、退保追回 | 直接佣金、阶梯、Override |
| 税务口径 | Premium Tax、Stamping Office 加签、1099-MISC / 1099-NEC 年报 | 增值税口径（预留） |
| 保司类型 | Admitted / Non-Admitted / Surplus Lines | （预留） |
| 业务数据 | `businessCountry = 'US'` | `businessCountry = 'CN'` |

> **关键约束：** businessCountry 是**数据层字段**，与 UI 语言切换（en-US/zh-CN）相互独立。切换 UI 语言不修改 businessCountry；US/CN 业务数据各自维持，不发生混读。i18n 只影响 UI 文案，不影响业务数据语义。

### 1.3 平台核心价值

- 从保险公司获取产品资源和出单权限
- 精细化授权给下游渠道使用（6 开关 + 限额继承）
- 实现佣金自动化计算和结算（含 Contingent Commission / Premium Tax / Stamping Office）
- 合规硬联动 + 白名单豁免（License 过期自动暂停 Appointment、CE 未达标暂停新单 Binding）
- 政策单向发布（我司下发保险公司政策，不接收渠道上报）
- 渠道订单全生命周期管理（本期建设，**从渠道商上报客户询价 Quote 起步**，6 种订单类型，含询价转化漏斗）
- 业务员 Individual Producer 全字段管理（NPN / License / Appointment / CE 学时进度 / 状态机）
- 国际化就绪（en-US + zh-CN，新增 channel.json 命名空间）

### 1.4 行业痛点（项目背景）

| 痛点 | 描述 | V1.0.3 应对 |
|---|---|---|
| 保险公司主数据分散 | 产品、费率、可售州、佣金方案散落在 Excel 和邮件中 | 主数据集中 + 审计可追溯 |
| 渠道层级复杂 | FMO → Agency → Branch → Agent 多级层级，Override 分润计算复杂 | 层级快照 + Override 引擎 |
| 合规风险高 | 州级监管，代理人需持牌 + Appointment + CE 才能出单，人工校验易遗漏 | 合规硬联动 + 白名单豁免 |
| 佣金结算低效 | 首年/续年递减、阶梯佣金、Override、Contingent、退保追回多维度规则 | 佣金引擎五阶段流水线 |
| 询价过程无系统承载 | 渠道商上报客户询价（Quote）、报价跟进、投保申请等前置环节散落在表格/邮件中，询价转化率不可见，出单后只能手工补录报单 | 询价订单（Quote）线上化：上报→报价→投保→核保→出单全状态流转 + 转化漏斗 |
| 多语言协作困难 | 需同时服务美国本地用户和中国运营团队 | i18n + channel.json 命名空间 + 术语库 |
| 业务员资质管理粗放 | 仅管理到渠道组织层，未细化到 Individual Producer | Individual Producer 全字段管理 |
| 政策传递失真 | 保险公司政策靠邮件/电话传达到渠道，时效与覆盖不可控 | 政策单向发布引擎 |
| 业务国别混读 | 同一系统同时承载 US/CN 业务易发生监管口径混读 | businessCountry 双轨分立 |

## 三、技术架构与核心引擎

### 3.1 系统架构原则

| 原则 | 说明 |
|---|---|
| 主数据集中 | 保险公司、产品、渠道、业务员（Individual Producer）四类核心主数据统一存储管理 |
| 引擎可配置 | 佣金规则、合规硬联动规则、政策发布规则引擎化配置，不硬编码。注：核保规则当前为文档化登记，自动执行待保司 API 开放 |
| 审计可追溯 | 所有序号变更、合规事件、政策下发、佣金计算、状态变更全链路审计，日志不可删除，保留期 ≥ 5 年 |
| 事件驱动 | 保单新单/续保/退保/批改事件通过消息队列驱动佣金计算与合规监测 |
| 国际化就绪 | react-i18next 框架，UI 文案外置 JSON 翻译文件，运行时切换；channel.json 命名空间独立维护 |
| 业务国别分轨 | businessCountry 字段（US/CN）贯穿数据层，与 UI 语言切换解耦 |
| 前置校验三件套 | 产品可售州 ∩ 渠道持牌州 ∩ 合作协议有效期 = 可授权范围 |
| 硬联动 + 白名单豁免 | 合规异常自动挂起关联实体，白名单命中则不挂起仅记录 |

### 3.2 佣金引擎（五阶段流水线）

```
数据采集 → 逐单计算 → 层级汇总(Override) → 调整处理 → 汇总生成结算单
```

**关键特性：**
- 事件驱动（保单事件异步触发）
- 快照机制（计算时冻结渠道层级 + 佣金方案版本）
- 增量计算 + 全量重算
- 断点续算
- 规则匹配采用"最具体优先"原则（多维维度权重评分，评分相同取最近更新）

**佣金类型体系（V1.0.3 美国保险口径补齐）：**
- 直接佣金（Direct Commission）
- Override 佣金（层级分润）
- 续期佣金（Renewal / Trail）
- Contingent Commission（或有佣金，按保司年度盈利触发）
- MGA 管理费
- 退保追回（Chargeback）
- 服务佣金（Service / Trail）

**资金四段式流转（V1.0.3 明确）：**

```
① 客户 → 保司（保费） → ② 保司返点给我司（佣金） → ③ 我司付渠道佣金（Override 后） → ④ 渠道收到佣金
```

### 3.3 合规硬联动引擎（V1.0.3 新增）

```
合规事件触发 → 检测关联实体 → 自动挂起（授权/合作/结算）→ 检查白名单 → 命中则不挂起仅记录 → 推送整改 → 复检通过后恢复
```

**关键特性：**
- 合规事件类型：License 过期、Appointment 失效、E&O 保险过期、CE 学时未达标、监管处罚
- 硬联动范围：自动暂停渠道授权（6 开关全关）、暂停合作协议、暂停结算单生成
- 白名单豁免：命中白名单（按渠道/产品/州/事件类型四维配置）则不挂起，仅记录合规事件
- 业务员 License 联动：License 过期自动暂停 Appointment；CE 未达标触发培训任务 + 暂停新单 Binding
- 整改复检：整改完成后由合规专员复检，复检通过后自动恢复授权/合作/结算
- 全程审计留痕，不可删除

### 3.4 政策单向发布引擎（V1.0.3 新增）

```
保司政策录入 → 我司政策适配（按险种/产品/州） → 政策下发到渠道 → 渠道接收回执 → 政策归档
```

**关键特性：**
- 单向下发：我司下发保险公司政策，**不接收渠道上报**
- 5 种政策类型：险种政策、产品政策、费率政策、承保政策、续保政策
- 时效：Permanent（永久）/ Term（有期限，自动到期）
- 接收回执：渠道确认接收政策，未接收提醒
- 政策归档：全量政策历史归档，可追溯查询
- 与授权联动：政策变更可触发授权范围重新评估

### 3.5 6 开关授权引擎（V1.0.3 新增）

| 开关 | 含义 | 默认 |
|---|---|---|
| 可报价（Quote） | 渠道可获取产品报价 | 关 |
| 可出单（Bind） | 渠道可绑定保单 | 关 |
| 可批改（Endorse） | 渠道可批改保单 | 关 |
| 可续保（Renew） | 渠道可续保 | 关 |
| 可退保（Cancel） | 渠道可退保 | 关 |
| 可理赔（Claim） | 渠道可发起理赔 | 关 |

**限额继承：** 子渠道限额 ≤ 父渠道限额；父渠道限额调整时，子渠道限额需重新校验。

### 3.6 出单合规校验链路（V1.0.3 恢复硬联动版本）

> **V1.0.2 移除说明：** V1.0.2 已移除自动合规校验链路，合规要求由线下流程保障。
>
> **V1.0.3 恢复说明：** V1.0.3 在渠道管理 7 大模块重组后，恢复硬联动合规校验链路，但仅作用于渠道侧，不覆盖保司侧（保司侧仍为登记制 + 审计）。

| 步骤 | 校验项 | 不通过处理 |
|---|---|---|
| 1 | 业务员 License（NPN / License States / License LOA） | 拦截 + 触发合规事件 |
| 2 | 业务员 Appointment（Carrier × State） | 拦截 + 触发合规事件 |
| 3 | 业务员 CE 学时进度 | 拦截 + 触发培训任务 + 暂停新单 Binding |
| 4 | 渠道持牌州 ∩ 产品可售州 | 拦截 |
| 5 | 渠道产品授权（6 开关：可出单 = ON） | 拦截 |
| 6 | 出单限额（子渠道 ≤ 父渠道） | 转人工核保或拦截 |
| 7 | E&O 保险有效性 | 拦截 + 触发合规事件 |
| 8 | 白名单豁免检查 | 命中则放行仅记录，未命中则拦截 |

所有拦截事件记录审计日志，不可删除，保留期不少于 5 年。

**渠道订单类型枚举（V1.0.3 本期建设，6 种）：**
- Quote（询价订单——渠道商上报客户询价，订单起点，不进结算）
- New Business（新单——询价确认、出单后由 Quote 转化）
- Renewal（续保）
- Endorsement（批改）
- Cancellation（退保）
- Reinstatement（复效）

**订单状态机（全生命周期 16 状态）：**
- 询价前段：DRAFT（草稿）→ QUOTE_SUBMITTED（询价已上报）→ QUOTED（已报价）→ QUOTE_ACCEPTED（报价已确认）→ APPLICATION_SUBMITTED（投保申请已提交）→ UNDERWRITING（核保中）
- 出单后段：BOUND（已成交，Quote 转化 New Business）→ LINKED（已绑定账单）→ PENDING_SETTLEMENT（待结算）→ SETTLED（已结算）
- 异常/终态：CHARGEBACK_PENDING/CHARGEBACK_DONE（退保追回）、DECLINED（拒保）、QUOTE_EXPIRED（报价失效）、QUOTE_WITHDRAWN（询价撤回）、VOID（作废）
- 结算口径：仅 BOUND 后成交订单参与佣金计算，询价/失效/撤回/拒保订单不进结算

**合规事件类型枚举：**
- LICENSE_EXPIRED（License 过期）
- APPOINTMENT_VOID（Appointment 失效）
- EO_INSURANCE_EXPIRED（E&O 保险过期）
- CE_CREDITS_INSUFFICIENT（CE 学时未达标）
- REGULATORY_ACTION（监管处罚）

## 五、核心业务场景

### 场景一：渠道商询价上报、报价出单 + 合规硬联动

```
① 渠道商上报客户询价（Quote Order）
   业务员在门户（或运营代录）录入：意向 Carrier/Product/LOB/State + 客户信息 + 风险明细 + 保障意向
   → 前置校验三件套（产品可售州 ∩ 渠道持牌州 ∩ 合作协议有效期）+ 可报价开关 can_quote
   → 状态 DRAFT → QUOTE_SUBMITTED
② 报价（保司 API 开放前：人工报价/费率档案试算登记；支持多产品对比、Re-quote 版本、30 天有效期）
   → QUOTED
③ 客户确认报价 → 完善信息/上传核保资料/电子签名 → 提交投保申请
   → QUOTE_ACCEPTED → APPLICATION_SUBMITTED → UNDERWRITING
④ 核保登记（自动/人工/加费/拒保）+ 8 步合规校验链路（V1.0.3 恢复硬联动版本）
⑤ 保司出单（Bound）→ 回填保单号/Binder/生效日 → Quote 转化为 New Business 成交订单
   → BOUND，触发佣金计算事件 → LINKED → PENDING_SETTLEMENT → SETTLED
```

**异常分支：**
- 报价超期未确认 → QUOTE_EXPIRED（可 Re-quote）；客户放弃 → QUOTE_WITHDRAWN；核保拒保 → DECLINED——均不进结算
- 合规校验不通过：拦截 + 触发合规事件 + 检查白名单豁免 → 命中白名单放行仅记录；未命中挂起授权/合作/结算，推送整改 → 复检通过 → 恢复

**V1.0.3 关键特性：**
- 订单起点前推：渠道订单从渠道商上报客户询价（Quote）开始，而非出单后补录；询价转化漏斗（上报→报价→确认→投保→成交）可视
- 本期与未来态边界：询价上报/报价登记/投保/核保进度/出单回填本期建设（登记制）；保司费率引擎实时报价、自动核保为未来态
- 业务员 License 联动：License 过期自动暂停 Appointment，进而拦截报价确认与出单
- CE 学时联动：CE 未达标触发培训任务 + 暂停新单 Binding
- 白名单豁免：四维配置（渠道/产品/州/事件类型），命中则不挂起仅记录
- 全程审计留痕；询价阶段客户 PII 最小化采集

### 场景二：佣金计算与结算（四段式流转）

```
结算周期触发 → 数据采集（保单事件） → 逐单计算（直接佣金 + Override + 续期 + Contingent）
→ 层级汇总（Override 分润） → 调整处理（追回/阶梯/人工/预支）
→ 生成结算单 → 多级审批（主管→财务→总经理） → 支付（ACH/支票/电汇） → 结果回写
→ 税务处理（Premium Tax + Stamping Office 加签 + 1099-MISC/1099-NEC 年报）
```

**V1.0.3 美国保险口径补齐：**
- Contingent Commission：按保司年度盈利触发，年度结算
- Premium Tax：按州税率计算，由保司代扣或我司申报
- Stamping Office 加签：合规州（如 CA）需加签印章
- 1099-MISC / 1099-NEC 年报：年度生成 1099 税表上报 IRS 与业务员

**资金四段式流转：**
1. 客户 → 保司（保费）
2. 保司返点给我司（佣金）
3. 我司付渠道佣金（Override 后）
4. 渠道收到佣金

### 场景三：渠道合规硬联动（V1.0.3 新增）

```
合规事件触发（如 License 过期） → 检测关联实体（业务员 + 渠道 + 产品 + 州）
→ 自动挂起（授权 6 开关全关 + 合作协议暂停 + 结算单暂停）
→ 检查白名单豁免
→ 命中白名单：不挂起仅记录合规事件
→ 未命中：保持挂起状态
→ 推送整改任务给业务员 + 渠道管理员
→ 整改完成（如 License 续证） → 合规专员复检
→ 复检通过 → 自动恢复授权/合作/结算
→ 全程审计留痕
```

### 场景四：渠道政策单向发布（V1.0.3 新增）

```
保司政策录入（含 5 种类型：险种/产品/费率/承保/续保）
→ 我司政策适配（按险种/产品/州筛选适用渠道）
→ 政策下发到渠道（按渠道授权范围精准推送）
→ 渠道接收回执（确认接收）
→ 政策归档（全量政策历史归档，可追溯查询）
→ 政策与授权联动（政策变更可触发授权范围重新评估）
```

**V1.0.3 关键约束：**
- 单向发布：我司下发保险公司政策，**不接收渠道上报**
- 时效：Permanent（永久）/ Term（有期限，自动到期）
- 适用范围：按险种/产品/州三维精准推送

## 八、关键风险与建议

### 8.1 高风险项

| 风险 | 影响 | 建议 |
|---|---|---|
| 佣金规则复杂度极高 | 多维匹配 + 阶梯 + Override + Contingent + 追回，测试用例爆炸 | 优先建设规则引擎测试沙盒 |
| 上游保司无 API | 账单/产品/牌照数据依赖人工录入与文件导入 | 建立数据校验规则、导入模板规范、双人复核机制 |
| 数据权限模型复杂 | 功能权限 × 数据权限（含 businessCountry US/CN）双重约束，易出越权问题 | 统一权限中间件，businessCountry 作为数据权限维度强制下沉到所有查询 |
| 合规硬联动误伤 | 白名单配置不当可能误挂起正常业务渠道 | 白名单配置需双人复核 + 审计留痕，建立 SOP |
| 业务员资质管理复杂 | Individual Producer 全字段管理 + License 联动 + CE 学时进度，数据量大 | 与 NIPR / 州 DOI 数据对接预留接口，本期人工维护 |
| 政策下发覆盖不全 | 政策适用范围配置错误可能导致部分渠道漏收 | 政策下发前预演推送范围，差异校验 |
| 对账差异处理依赖人工 | 差异核实、备注、处理均需人工跟进，效率与一致性风险 | 建立差异处理 SOP 与跟进提醒机制，差异记录不可删除 |

### 8.2 架构建议

1. **佣金引擎独立服务化** — 计算密集，需独立部署和扩容
2. **层级关系需快照机制** — 佣金计算时冻结层级，避免调整影响历史
3. **事件驱动架构** — 保单事件 → 消息队列 → 佣金计算 / 合规监测，解耦核心流程
4. **审计日志统一设计** — 所有实体变更（含合规事件、政策下发、订单状态）统一走审计中间件
5. **businessCountry 强制下沉** — 所有渠道侧查询接口强制带 businessCountry 过滤，避免 US/CN 数据混读
6. **白名单配置双人复核** — 白名单是合规硬联动的关键豁免点，配置需双人复核 + 审批

## 九、总结

本项目是一个**高复杂度的 B2B 保险中台系统**，核心难点在于：

1. **佣金计算引擎** — 多维规则匹配 + 层级 Override + Contingent + 退保追回的叠加复杂度
2. **多层级组织架构** — 多上级、按保险公司/业务线分维度汇报
3. **中间授权模式** — 我司作为平台方的"产品接入 → 授权（6 开关 + 限额继承）→ 出单"链路设计
4. **保司佣金对账** — 按协议佣金率试算与保司账单逐笔比对，差异人工处理，原始数据不可重复/删除
5. **合规硬联动 + 白名单豁免**（V1.0.3 新增）— License/Appointment/CE/E&O 多维合规事件自动挂起关联实体，白名单豁免
6. **业务国别分轨**（V1.0.3 新增）— US/CN 业务数据层分轨，与 UI 语言切换解耦
7. **Individual Producer 全字段管理**（V1.0.3 新增）— 业务员层级管理，NPN / License / Appointment / CE 学时进度 / 状态机
8. **政策单向发布**（V1.0.3 新增）— 我司下发保险公司政策，5 种类型，Permanent/Term 时效
9. **渠道订单全链路（含询价）**（V1.0.3 新增）— 渠道商上报客户询价（Quote）→报价→投保→核保→出单→结算的状态机设计、询价转化关系（parent_order_id）、未成交订单与结算口径隔离

需求文档功能点定义到操作级（**115 个功能点**：保司 41 + 渠道 62（含渠道订单 3 项，单列独立子模块） + i18n 12），质量整体优秀，可直接进入技术方案设计和工作量评估阶段。
