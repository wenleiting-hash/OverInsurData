## 二、数据表设计

迁移脚本 `ovwr-migration-channel-auth-v1011.sql`，三张新表 + 种子数据 + 两项种子修复：

### 2.1 `channel_org` — 渠道主数据

| 列 | 类型 | 说明 |
|---|---|---|
| `channel_id` | varchar PK | 渠道编码（c1–c12） |
| `channel_name` / `channel_type` | varchar | 名称 / 类型（Broker、Independent Agency、MGA 等） |
| `status` | varchar | active / inactive / onboarding / suspended（只有 active 可被授权） |
| `tier` / `parent_id` | varchar | 渠道等级 / 父渠道（层级渠道） |
| `hq_state` | varchar | 总部所在州 |
| `licensed_states` | jsonb | 持牌州列表（授权州必须与其取交集） |
| `npn_code` / `manager_name` | varchar | NPN 编码 / 负责人 |
| `deleted` | boolean | 软删 |

种子：12 个渠道（来自前端原型 mockData，c1–c8 为独立渠道、c9 onboarding、c10 suspended、c11/c12 为 c1/c2 子渠道）。

### 2.2 `channel_product_authorization` — 渠道产品授权（10.1）

| 列 | 类型 | 说明 |
|---|---|---|
| `auth_id` | varchar PK | 授权 ID（`cha_` 前缀） |
| `channel_id` | varchar FK→channel_org | 被授权渠道 |
| `product_id` | varchar FK→insurance_product | 授权产品 |
| `carrier_id` | varchar FK→insurance_carrier | 冗余保司（随产品写入，便于筛选） |
| `line_of_business` | varchar | 险种（取自产品） |
| `authorized_states` | jsonb | 授权销售州，必须 ⊆ 产品可售州 ∩ 渠道持牌州 |
| `grant_type` | varchar | permanent 永久 / fixed 固定期限 / trial 试用 |
| `effective_date` / `expiration_date` | date | 生效日 / 到期日（fixed、trial 必填到期日） |
| `status` | varchar | active / revoked |
| `revoked_at` / `revoke_reason` | timestamp / varchar | 收回审计字段 |
| `created_by` / `created_at` / `updated_at` | — | 审计 |
| `deleted` | boolean | 软删 |

约束：唯一部分索引 `uq_channel_product_auth_active (channel_id, product_id) WHERE deleted=FALSE AND status<>'revoked'`——同一渠道同一产品只允许一条有效授权（冲突返回 409），收回后允许重新授权。

**读时派生状态**（不落库）：`effective_status` = active 且 30 天内到期 → `expiring`；到期日已过 → `expired`；其余取 status。

### 2.3 `channel_issuance_permission` — 出单权限与限额（10.2）

与授权 1:1（`auth_id` UNIQUE FK，级联删除）：

| 列 | 说明 |
|---|---|
| `can_quote` / `can_bind` / `can_endorse` / `can_renew` / `can_surrender` / `can_claim_report` | 六个操作开关：报价 / 出单 / 批改 / 续保 / 退保 / 理赔报案 |
| `bind_mode` | direct 直接出单 / underwrite 转保司核保 / forbidden 禁止出单（forbidden 时服务端强制 can_bind=FALSE） |
| `limit_per_policy` / `limit_monthly` / `limit_quarterly` | 单保单 / 月度 / 季度保费限额（numeric, ≥0） |
| `over_limit_rule` | manual 人工处理 / forbidden 拒绝 / approval 主管审批 |
| `updated_by` / 时间戳 | 审计 |

### 2.4 种子数据修复（迁移内置，可重复执行）

历史测试清理把上游主数据软删了，授权链路无可选项，迁移自动修复：

1. 恢复"拥有 Active 产品"的保司 `deleted=FALSE, status='active'`，跳过与现有保司 NAIC 部分唯一索引冲突的记录（本次恢复 c1001/c1005/c1008 三家；c1002 Chubb 因测试保司占用 NAIC 12345 跳过）。
2. 恢复全部 `status='Active'` 的种子产品 `deleted=FALSE`（同样跳过 product_code 冲突，本次恢复 8 个）。

## 三、后端实现（carrier-service）

新增模块 `apps/carrier-service/src/modules/channel/`，已注册进 `app.module.ts`。全部端点挂 `JwtAuthGuard`，写操作要求 super_admin / ops_manager，写审计到 `auth_operation_log`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/channels` | 渠道主数据列表（status / q 筛选），授权弹窗与 Tab 选择器数据源 |
| GET | `/api/channel-authorizations` | 授权列表，支持 channelId / carrierId / productId / status / q 筛选；JOIN 渠道、产品、保司、权限四张表，返回 effective_status 与权限/限额字段 |
| GET | `/api/channel-authorizations/:id` | 授权详情（含权限行） |
| POST | `/api/channel-authorizations` | 新建授权（201） |
| PUT | `/api/channel-authorizations/:id` | 编辑授权（仅 status=active 可改，revoked/expired 拒绝 400） |
| PATCH | `/api/channel-authorizations/:id/status` | body `{action:'revoke', reason}` 收回；`{action:'renew', expiration_date?}` 续期（不传新到期日则旧到期日 +365 天） |
| PUT | `/api/channel-authorizations/:id/permissions` | upsert 六操作开关 / bind_mode / 三项限额 / 超限规则 |

**业务校验（create/update）**：

- 渠道必须存在且 `status='active'`（onboarding/suspended 拒绝）；
- 产品必须存在且 `status='Active'`；
- 授权州必须 ∈ `product.available_states` ∩ `channel.licensed_states`；不传州时默认取两者交集（交集为空则 400）；
- grant_type 为 fixed / trial 时 expiration_date 必填；
- 同渠道同产品有效授权唯一（23505 → 409）；
- bind_mode=forbidden 时强制 can_bind=false（服务端口径，不信任前端）。

文件：`channel.controller.ts`、`channel.service.ts`、`channel.module.ts`、`dtos/channel-auth.dto.ts`。注意 DTO 类声明顺序：`UpsertIssuancePermissionDto` 必须在 `CreateChannelAuthorizationDto` 之前（嵌套校验装饰器的元数据引用存在 TDZ）。
