### Phase 1 — 数据库建表与种子数据

**目标**：创建 6 张核心业务表，灌入与 mock 数据对齐的种子数据

#### 1.1 insurance_carrier（保险公司档案表）

基于 `数据库设计方案_V2.1.md` 3.1 节，扩展字段以覆盖前端 `InsuranceCarrier` 接口的全部属性：

```sql
CREATE TABLE insurance_carrier (
  carrier_id       VARCHAR(32) PRIMARY KEY,
  naic_code        VARCHAR(8) NOT NULL UNIQUE,
  carrier_name     VARCHAR(128) NOT NULL,
  carrier_name_short VARCHAR(64),
  carrier_type     VARCHAR(16) DEFAULT 'ADMITTED',    -- ADMITTED / NON_ADMITTED
  status           VARCHAR(16) DEFAULT 'active',      -- active / inactive / pending
  region           VARCHAR(32),                       -- National / Northeast / Southeast / Midwest / West
  state            CHAR(2),                           -- 总部所在州
  coop_type        VARCHAR(32),                       -- direct / mga / wholesale / independent / platform
  coop_status      VARCHAR(16) DEFAULT 'active',      -- active / expiring / pending / suspended / terminated
  founded_year     INTEGER,
  website          VARCHAR(256),
  loss_ratio       NUMERIC(5,4),
  renewal_rate     NUMERIC(5,4),
  revenue          BIGINT,
  policy_count     INTEGER,
  commission_income BIGINT,
  am_best_rating   VARCHAR(8),
  sp_rating        VARCHAR(8),
  moodys_rating    VARCHAR(8),
  fitch_rating     VARCHAR(8),
  settlement_cycle VARCHAR(16) DEFAULT 'Monthly',     -- Monthly / Quarterly
  contract_expiry  DATE,
  channel_count    INTEGER DEFAULT 0,
  product_count    INTEGER DEFAULT 0,
  lines            JSONB DEFAULT '[]',                -- ["Auto","Home"]
  deleted          BOOLEAN DEFAULT FALSE,
  created_at       TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
  updated_at       TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

索引：`naic_code`(unique)、`status`、`region`、`coop_status`

#### 1.2 insurance_product（保险产品表）

```sql
CREATE TABLE insurance_product (
  product_id        VARCHAR(32) PRIMARY KEY,
  carrier_id        VARCHAR(32) NOT NULL REFERENCES insurance_carrier(carrier_id),
  naic_code         VARCHAR(16),
  product_name      VARCHAR(128) NOT NULL,
  short_name        VARCHAR(64),
  product_code      VARCHAR(32) NOT NULL,
  naic_form_number  VARCHAR(32),
  description       TEXT,
  description_en    TEXT,
  coverages         JSONB DEFAULT '[]',               -- ["Liability","Comprehensive",...]
  line_of_business  VARCHAR(16) NOT NULL,              -- AUTO / HOME / LIFE / HEALTH / COMMERCIAL / P&C
  sub_line          VARCHAR(32),
  product_type      VARCHAR(32),                       -- Individual / Group / VoluntaryBenefits
  insurer_id        VARCHAR(32),                       -- 冗余 carrier_id 别名
  insurer_name      VARCHAR(128),                      -- 冗余保险公司简称
  underwriting_mode VARCHAR(16) DEFAULT 'Auto',        -- Auto / Manual / MGA
  max_policy_limit  NUMERIC(12,2),
  mga_negotiation   BOOLEAN DEFAULT FALSE,
  renewal_type      VARCHAR(32),                       -- Guaranteed / Conditional / Non-Renewable
  policy_term_years INTEGER,
  age_min           INTEGER,
  age_max           INTEGER,
  exclude_dui       BOOLEAN DEFAULT FALSE,
  refer_high_value  BOOLEAN DEFAULT FALSE,
  refer_threshold   NUMERIC(12,2),
  blacklist_conditions JSONB DEFAULT '[]',
  available_states  JSONB DEFAULT '[]',                -- ["CA","NY","TX"]
  effective_date    DATE,
  expiration_date   DATE,
  status            VARCHAR(16) DEFAULT 'Active',      -- Active / Paused / Inactive / Pending
  is_active         BOOLEAN DEFAULT TRUE,
  rate_type         VARCHAR(16),                       -- Flat / Tiered / UsageBased
  base_rate         NUMERIC(10,4),
  min_premium       NUMERIC(10,2),
  max_premium       NUMERIC(10,2),
  rate_factors      JSONB DEFAULT '[]',
  premium_ytd       NUMERIC(14,2) DEFAULT 0,
  policy_count      INTEGER DEFAULT 0,
  avg_premium       NUMERIC(10,2) DEFAULT 0,
  loss_ratio        NUMERIC(5,4) DEFAULT 0,
  renewal_rate      NUMERIC(5,4) DEFAULT 0,
  documents         JSONB DEFAULT '[]',
  deleted           BOOLEAN DEFAULT FALSE,
  created_at        TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
  updated_at        TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```

索引：`carrier_id`、`line_of_business`、`status`、`product_code`(unique)

## 四、技术设计决策

| 决策 | 说明 |
|------|------|
| **数据库连接** | 复用现有 PG 连接池（`ovwr_db` 同一实例），`carrier-service` 直接 `pool.query` 或 Drizzle |
| **主键策略** | `VARCHAR(32)` 字符串 ID（`c1001`/`p1001`/`coop001`），与前端 mock 数据 ID 对齐 |
| **软删除** | `deleted BOOLEAN DEFAULT FALSE` + 全局 `WHERE deleted = FALSE` |
| **JSONB 字段** | `lines`、`coverages`、`available_states`、`tags`、`product_scope` 等数组/对象使用 JSONB |
| **冗余字段** | `insurer_name` 冗余到 product 表，避免 JOIN；后续可改为 join 查询 |
| **Mock 兜底** | API Client 层保留 mock fallback，`try/catch` 降级到 mock 数据 |
| **种子数据幂等** | `INSERT ... ON CONFLICT DO NOTHING` 保证可重复执行 |
| **代码分割** | 视图文件已通过 `lazy(() => import(...))` 实现代码分割，无需额外处理 |
| **分阶段交付** | Phase 1-2 后端先行 → Phase 3-4 前端对接 → Phase 5 Schema 归档 → Phase 6 验证 |
