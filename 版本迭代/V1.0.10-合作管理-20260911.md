### Phase 1 — 数据契约对齐与数据库迁移

**目标**：先修正契约，再扩表。契约不欠债，后续接线一次做对。

#### 1.1 前端 Record 类型修正

修改 `apps/web-carrier-admin/src/lib/user-api-client.ts`，按本文件 1.3 节对照表重写 `CooperationRecord` / `ContractRecord` / `SettlementRecord` / `ContactRecord` 四个接口（全部 snake_case，与后端 `SELECT *` 返回逐字段对齐），同步修正 `CooperationManagementView.tsx` L427-438 的映射（`insurer_short`、`settlement_cycle_days`、`premium_collection`、`premium_settlement`）。

#### 1.2 partnership 表终止流程扩展

新建迁移 `seed-data/ovwr-migration-cooperation-v1010.sql`：

```sql
ALTER TABLE carrier_partnership
  ADD COLUMN IF NOT EXISTS terminate_reason       VARCHAR(64),   -- 稳定原因码（见 2.4 枚举）
  ADD COLUMN IF NOT EXISTS terminate_note         TEXT,          -- 补充说明
  ADD COLUMN IF NOT EXISTS terminate_effect_type  VARCHAR(16),   -- immediate / end-of-term / scheduled
  ADD COLUMN IF NOT EXISTS terminate_effective_at TIMESTAMPTZ,   -- scheduled 生效时间
  ADD COLUMN IF NOT EXISTS terminated_at          TIMESTAMPTZ,   -- 实际终止落库时间
```

设计与产品模块 `pending_change` 完全同构：定时终止先写 `pending_change` 返回 `{ scheduled: true }`，状态仍为 `Approved`；到点由扫描器执行后置 `Terminated`。

#### 1.3 续约任务表 carrier_renewal_task

```sql
CREATE TABLE carrier_renewal_task (
  renewal_id       VARCHAR(32) PRIMARY KEY,
  partnership_id   VARCHAR(32) NOT NULL REFERENCES carrier_partnership(partnership_id),
  carrier_id       VARCHAR(32) NOT NULL REFERENCES insurance_carrier(carrier_id),
  contract_id      VARCHAR(32) REFERENCES carrier_contract(contract_id),
  title            VARCHAR(256) NOT NULL,
  expiry_date      DATE NOT NULL,
  priority         VARCHAR(16) DEFAULT 'normal',   -- critical / high / normal / low
  status           VARCHAR(24) DEFAULT 'upcoming', -- upcoming / in-negotiation / renewed / expired
  auto_renew       BOOLEAN DEFAULT FALSE,
  account_manager  VARCHAR(128),
  last_action      VARCHAR(256),
  last_action_at   DATE,
  deleted          BOOLEAN DEFAULT FALSE,
  created_at       TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
  updated_at       TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_renewal_expiry ON carrier_renewal_task(expiry_date) WHERE deleted = FALSE;
```

**任务来源策略（技术决策）**：续约任务以本表为准，由后端 `syncRenewalTasks()` 从数据源 upsert 生成——
数据源 = `carrier_contract`（expiry_date 在未来 200 天内或已过期 30 天内、status active/expiring/expired）∪ `carrier_partnership`（expiration_date 同窗口、status Approved）。
触发时机：合作/合同写操作后 + GET /api/renewals 入口懒触发（与产品模块"写后维护 + 读时懒执行"一致），不做高频全表定时任务。`priority` 按到期天数懒计算（<0=critical 已过期、≤60=high、≤120=normal、其余 low），存储值可被人工覆盖。

#### 1.4 产品资源接入申请表 carrier_product_access_request


### Phase 2 — 后端 API 补齐

**目标**：新增 16 个端点 + 增强 1 个端点，全部落在 cooperation 模块（contract/contacts 的全局查询也在该模块内实现，不新开模块）。

#### 2.1 合作终止增强

`PATCH /api/cooperations/:id/terminate` 请求体扩展：

```typescript
class TerminateCooperationDto {
  @IsString() @IsNotEmpty() reason!: string;        // 原因码，见枚举
  @IsOptional() @IsString() note?: string;
  @IsOptional() @IsIn(['immediate','end-of-term','scheduled']) effectType?: string;
  @IsOptional() @IsString() effectiveAt?: string;    // ISO 时间，effectType=scheduled 时必填且必须晚于当前
}
```

行为：

| effectType | 行为 |
|-----------|------|
| `immediate`（默认） | 立即置 Terminated，写 terminated_at + 审计 `COOP_TERMINATE` |
| `end-of-term` | 校验 expiration_date 非空；写 pending_change，effective_at=到期日 00:00；审计 `COOP_TERMINATE_SCHEDULED` |
| `scheduled` | 校验 effectiveAt > now；写 pending_change；审计同上 |

- 原因码枚举（与 UI REASONS 顺序对齐）：`contract-expired` / `compliance-issue` / `strategy-adjustment` / `mutual-agreement` / `counterparty-request` / `performance-issue` / `other`，label 仅在 i18n 维护。
- 定时扫描：`CooperationService` 实现 `OnModuleInit`（启动 10s 后 + 每 60s），扫描到期 pending_change 执行终止，审计 action `COOP_TERMINATE`、extra_data.source='scheduler'；`getList/getById` 入口加懒执行 `await this.applyDueChanges()`（与产品模块完全同构）。
- 当前合作必须为 `Approved`，否则 400。

#### 2.2 合同端点（新增 4 个）

| 方法 | 路径 | 功能 |
|------|------|------|
| `GET` | `/api/contracts` | 全局合同列表（contracts Tab 使用），query: carrier/status/type；JOIN 返回 `insurer_short`；**输出附加计算列** `effective_status`：active 且 expiry_date < today → `expired`；active 且 30/90 天内到期 → `expiring`（前端"即将到期"角标口径以后端为准） |
| `PUT` | `/api/cooperations/:id/contracts/:contractId` | 更新合同（白名单字段，同 createContract 的 11 个业务字段 + `file_url` + `status`） |
| `DELETE` | `/api/cooperations/:id/contracts/:contractId` | 软删除；若磁盘存在旧 file_url 对应文件，best-effort unlink（安全规则照搬产品材料模块：UPLOAD_DIR + basename + resolve + sep 前缀校验） |
| `PATCH` | `/api/cooperations/:id/contracts/:contractId/status` | 状态流转，body `{status}`；允许 `draft→negotiating→pending-sign→active→expiring/expired→terminated` 顺序内跳转（终态 expired/terminated 不可逆） |

`CreateContractDto` 增加 `@IsOptional() @IsString() file_url?: string`；新建合同流程 = 先 `POST /api/uploads` 拿 url，再 POST 合同。

#### 2.4 结算 upsert

`PUT /api/cooperations/:id/settlement` 改为 **upsert 幂等语义**：配置不存在时以合作的 carrier_id 新建（INSERT ... ON CONFLICT(partnership_id) DO UPDATE），不再返回 404；响应统一返回配置行。字段白名单：cycle / bill_cutoff_day / payment_term_days / payment_method / billing_format / api_enabled / premium_collection；写 `updated_by`、`last_updated=NOW()`。

#### 2.5 续约端点（新增 4 个）

| 方法 | 路径 | 功能 |
|------|------|------|

### Phase 5 — 审计日志与通用审计服务

**目标**：合作模块全部写操作落 `auth_operation_log`，并把产品模块的审计经验沉淀为共享服务。

| **契约先于功能** | Phase 1 先修 3 组 Record/列名偏差再接视图，避免重蹈"前端按想象字段接线"覆辙 |
| **pending_change 同构** | 定时终止复用产品模块 V1.0.10 已验证的 jsonb + 扫描器 + 读时懒执行方案，不引入新调度框架 |
| **续约任务表 + 懒 sync** | 续约是派生业务数据，采用"合同/合作到期数据 upsert 生成任务 + 写后/读时同步"，不做高频定时全表扫描 |
| **合同到期状态实时计算** | expired/expiring 不回写库，由 GET 端点输出 effective_status，消除"状态过期但库里还 active"的数据腐化 |
| **结算 PUT upsert** | 配置为合作的 0..1 从属资源，PUT 天然幂等，不存在即创建，去掉 404 分支与前端额外判断 |
| **主联系人单事务互斥** | 同 carrier+partnership 维度先全量置 false 再置 true，避免双主联系人 |
| **接入状态机后端强校验** | 5 步流水线 + rejected/suspended 的合法跳转白名单在后端维护，前端只做按钮显隐 |
| **废弃 mock fallback** | V1.0.8 的"API 失败降级 mock"策略本版移除：真实数据已在库，降级只会制造"数据还在"的假象 |
| **合同文件复用通用上传** | /api/uploads 已含类型/大小/文件名/静态服务完整能力，合同模块只存 file_url，不建第二套上传 |
| **视图拆分目录** | 1,136 行单文件拆为壳 + tabs + components，App 懒加载入口名不变，零路由改动 |
| **审计共享化** | 产品模块验证过的长度/JSONB 防护沉淀到 common AuditService，顺手消除 user/department 旧隐患 |
| **状态大小写口径** | 合作级 PascalCase（Approved/Terminated），子资源小写/kebab-case（active/pending-sign/in-review），与库内现有数据一致，不做数据迁移 |

### 12.2 状态机（服务端白名单）

旧审批词汇迁移（迁移脚本 `seed-data/ovwr-migration-coop-lifecycle-v1012.sql`，可重复执行）：Draft/Rejected→Negotiating；Submitted/UnderReview→PendingSign；Approved→Active；新增 Signed（已签未生效）；Terminated 不变；**Expiring/Expired 不入库**，读时派生（Active 且到期日 ≤90 天 / 已过期），CHECK 约束 `chk_partnership_status` 限 5 个入库值。

```
Negotiating → PendingSign                       （推进，可逆）
PendingSign → Negotiating | Signed              （回退 / 签署）
Signed      → PendingSign | Active              （退回 / 手动开始履行；生效日到达系统自动 → Active）
Active      → Terminated                        （仅经 PATCH /terminate：原因 + 生效方式）
Terminated  → （终态只读）
```

- PUT 携带 status 逐条白名单校验，越权跳转 400；Terminated 不可经 PUT 设置。
- 立即终止直接落 Terminated；到期/指定日期终止写 `pending_change`，由 60s 轮询 + 读时惰性扫描执行；新增 `applyDueActivations()`（Signed 到期自动 Active，审计 COOP_ACTIVATE）。
- 续约任务同步条件 `status='Approved'` 改为 `'Active'`。

### 12.3 端点（V1.0.12 新增/增强）

| 方法/路径 | 说明 |
|---|---|
| `DELETE /api/cooperations/:id` | 状态 ∉ {Negotiating, PendingSign} 返回 400；软删 + COOP_DELETE 审计 |
| `DELETE /api/cooperations/batch`（body `{ids:string[]}`） | 批量软删；SQL 以 `status = ANY(ARRAY['Negotiating','PendingSign'])` 过滤，不可删/不存在计入 skipped，返回 `{deleted, skipped}`，逐条审计（params.batch=true）；空数组 400；**字面量路由声明在 `:id` 之前** |
| `PUT /api/cooperations/:id` | 编辑锁：existing.status ∈ {Active, Terminated} 直接 400；洽谈中/待签约/已签约可改；续约执行/排期扫描走独立 SQL 不受影响 |
