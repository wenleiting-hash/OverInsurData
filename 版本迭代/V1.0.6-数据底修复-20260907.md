## 一、问题清单

### A. 数据库层问题（15 项）

#### A-1 P0 严重（运行时必崩）

| # | 问题 | 根因 |
|---|------|------|
| DB-1 | 三套冲突的用户表 Drizzle Schema | `auth-user-schema-ovwr.ts` (integer PK) vs `overinsur-auth.ts` (varchar PK) vs `permission-schema-ovwr.ts` (ovwr_ 前缀) |
| DB-2 | auth.service 与 user.service 查询字段互斥 | auth.service 查 `real_name, status='1'`; user.service 查 `name_zh, name_en, mfa_enabled, deleted` |
| DB-3 | 主键类型不一致 | auth.service 用 VARCHAR UUID, Drizzle 定义 integer, user.service 用 user_uuid VARCHAR |
| DB-4 | 外键引用错误 | `permission-schema-ovwr.ts`: role_permission FK 引用 user_role 表而非 role 表 |
| DB-5 | user_role 表三套不同结构 | 三个 schema 文件分别定义了不同的 PK 类型和列 |

#### A-2 P1 重要（功能无法正常）

| # | 问题 | 根因 |
|---|------|------|
| DB-6 | 原型需要的字段缺失 | auth_user 无 auth_type, remark, created_by 列 |
| DB-7 | sys_department 表未定义 | user.service 引用 sys_department 但无建表脚本 |
| DB-8 | 部门字段命名冲突 | schema 用 dept_id+dept_code; user.service 用 dept_code |
| DB-9 | auth_operation_log 字段缺失 | user.service logAudit 插入 target_type, target_id, success, request_params 列但 schema 无此定义 |
| DB-10 | 操作日志表三套重复定义 | 三个文件各定义一次且表名/列名不同 |
| DB-11 | 角色表 Schema 冲突 | Drizzle 有 permission_keys/is_system/deleted; SQL 脚本有 type 无 is_system |
| DB-12 | 刷新令牌表重复定义 | permission-schema-ovwr.ts 和 overinsur-auth.ts 各定义一次 |

#### A-3 P2 一般

| # | 问题 | 根因 |
|---|------|------|
| DB-13 | 三套 SQL 脚本互相冲突 | create-auth-tables.sql, ovwr-auth-db.sql, create-ovwr-schemas.sql |
| DB-14 | 种子数据密码 hash 错误 | 脚本注释为 Admin@123456 但前端演示用 admin123 |
| DB-15 | 种子角色数量不足 | 仅 3 个角色，原型需要 5 个 |

## 三、Schema V5 核心设计决策

| 决策 | 说明 |
|------|------|
| **主键策略** | `integer id` (SERIAL) 为 Drizzle ORM 主键 + `user_uuid` (VARCHAR 36) 为业务标识符 |
| **业务标识符** | JWT payload、API 响应、前端引用均使用 `user_uuid` |
| **用户名字段** | `name_zh` + `name_en` 替代旧的 `name` / `real_name` |
| **状态枚举** | `active` / `inactive` / `locked` / `pending` (varchar 16) |
| **认证方式** | `auth_method` varchar(16) 支持 `local` / `sso` / `ldap` |
| **账户锁定** | `failed_login_attempts` >= 5 时自动锁定 30 分钟 |
| **软删除** | `deleted` boolean 列 + `WHERE deleted = FALSE` 查询条件 |

## 五、数据库初始化

执行统一建库脚本：

```bash
# 方式一：通过 Node.js 脚本
cd insurance-platform
node seed-data/run-auth-init.js

# 方式二：通过 psql（如已安装）
psql -h localhost -U postgres -d ai_saas -f seed-data/auth-init.sql
```

种子数据：
- **6 个部门**：技术部、运营部、财务部、渠道部、合规部、市场部
- **5 个角色**：超级管理员、运营管理员、渠道经理、财务专员、只读用户
- **1 个管理员**：admin / admin123 (bcrypt hash)
