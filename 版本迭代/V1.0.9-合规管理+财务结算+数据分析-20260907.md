## 五、前端视图 mock → API 迁移

### 5.1 迁移策略

每个视图的迁移步骤：
1. 引入对应的 React Query Hook
2. 替换 mock 数据引用为 Hook 返回的 `data`
3. 添加 `isLoading` 骨架屏 + `error` 错误状态 + 空数据空状态
4. 替换本地操作（toggle/create/delete）为 `useMutation` + `invalidateQueries`
5. 删除内联 mock 数据和 mock import
6. 移除多余的 padding（遵循 Layout `p-6` 规范）

## 八、风险与注意事项

| 风险项 | 说明 | 应对措施 |
|--------|------|---------|
| **数据分析聚合性能** | 分析模块需从多表聚合大量数据，实时查询可能慢 | 预留物化视图 / 定时聚合任务方案 |
| **财务文件上传** | 账单文件上传（CSV/Excel/PDF/EDI）需后端解析 | Phase 2 先实现元数据存储，文件解析延后到 V1.10 |
| **OFAC 外部数据源** | OFAC 筛查需对接外部制裁名单 API | Phase 2 先用本地数据库模拟，V1.10 对接真实 API |
| **NIPR 外部接口** | NIPR 牌照校验需对接 NIPR 网关 | Phase 2 先记录校验请求，V1.10 对接真实 NIPR API |
| **旧版财务视图清理** | 6 个独立视图（~2,349 行）功能已被统一视图覆盖 | 本迭代保留路由注册但标注 deprecated，V1.10 清理 |
| **Recharts 数据格式对齐** | 后端聚合结果需与前端 Recharts 数据格式一致 | API 响应格式以 `insurerAnalyticsData.ts` 现有结构为契约 |
| **Layout padding 叠加** | 部分合规视图有 `min-h-screen` + 内联 padding | 统一移除，依赖 Layout `<main p-6>` |
