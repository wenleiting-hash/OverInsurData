## 一、背景与目标

V1.0.9 已搭建合规模块的完整骨架：后端 `modules/compliance/`（controller + service + schema，6 张表）、前端 7 个合规视图（已挂路由）、service/hook 数据层。但经逐端点、逐视图核查，**前后端从未真正联调**：

- 后端：controller 全部 `dto: any`（无 DTO 校验）、写操作无审计日志、OFAC 筛查无真实匹配逻辑、dashboard 告警恒为空、牌照校验/报告生成为假流程；
- 前端：4 个视图存在 snake_case/camelCase 契约错配（列表渲染不出）、筛查/复核/拦截放行/牌照校验按钮未接 mutation、报告页纯 mock、大量硬编码英文、使用 `window.confirm()`/`alert()`/`setTimeout` 假态。

**本迭代目标**：让 4.5–4.9 各页面与后端真实 API 全链路打通，数据可查、动作可写、写操作有审计、交互符合《通用组件与通用交互规范_V1.0》。

## 三、后端改造（carrier-service/modules/compliance）

### 3.1 DTO 校验（替换全部 `dto: any`）

新建 `dtos/compliance.dto.ts`（class-validator + class-transformer）：

- `CreateRuleDto / UpdateRuleDto / ToggleRuleDto`
- `OfacScreenDto`（entity_name 必填、entity_type 枚举 individual/company/vessel、country 可选字符串、policy_id 可选）
- `OfacReviewDto`（result: clear/watchlist/blocked、review_note、override_approved、reviewed_by）
- `ResolveInterceptionDto`（resolved_status: released/rejected/escalated、reviewed_by、override_note、release_note）
- `VerifyLicenseDto`（license_ids: string[]，最多 50）
- `GenerateReportDto`（report_name、category、period、format: pdf/xlsx/csv、recipients?: string[]）

注意全局 ValidationPipe 可能 `forbidNonWhitelisted`：只声明前端实际发送字段；`?:` 可选字段不得误发。

### 3.2 审计日志

写操作接入 `common/audit.service.ts`，module='compliance'：

| 动作 action | 触发端点 |
|-------------|----------|
| COMPLIANCE_RULE_CREATE / UPDATE / DELETE / TOGGLE | rules 写操作 |
| OFAC_SCREEN / OFAC_REVIEW | ofac/screen、ofac/:id/review |
| INTERCEPTION_RESOLVE | interceptions/:id/resolve |
| LICENSE_VERIFY | licenses/verify |
| REPORT_GENERATE | reports/generate |

注意：审计 id/user_id 列为 varchar(32)，UUID 去横杠；jsonb 参数显式 `$n::jsonb`；表为 auth_operation_log（request_params text / extra_data jsonb）。

### 3.3 真实业务语义

1. **OFAC 初筛 screenOFAC**：内置可配置小名单（种子化常量，含典型 SDN 名称/别名/程序标签），按 entity_name 做归一化（大小写、标点、空白）精确 + 包含/别名匹配，产出：
   - 完全命中 → blocked、match_score≥90、level=high、写 matched_entry/matched_list/program；
   - 模糊/部分 token 命中 → watchlist（60–89，medium）；
   - 无命中 → clear（<60）；
   - 同步写 screened_by、timestamp、details_json。
2. **牌照列表状态读时派生**：以 expiry_date 为准派生 expired（< 今天）/ expiring（≤30 天）/ active；verification_status 保留库值；不在写库时改状态。
3. **到期提醒懒同步**：GET license-reminders 时由 nipr_license 的 expiry_date 按 60/30/7/0 天窗口 upsert reminder（参照合作模块 syncRenewalTasks 的 upsert 模式），再返回 JOIN 列表（license_number/state/license_type/expiry_date/channel_name）。
4. **dashboard recent_alerts**：联合查询——未解决 blocked 拦截（取最新 5）+ OFAC watchlist/blocked 未复核（最新 5）+ 7 天内到期牌照（最新 5），统一 `{type, level, title, ref_id, at}` 结构，最多 10 条倒序。
5. **verifyLicenses**：无外部 NIPR API，明确语义为"内部核验"——逐牌照校验 expiry_date/status/CE 学时，写回 last_verified_at、verification_status（verified/failed + 原因入 details），返回逐条结果数组；不假装外部成功。
6. **generateReport**：按 category/period 真实 count 聚合（规则命中/OFAC/拦截/牌照四类来源），写 record_count、file_size 文本、generated_by、generated_at、status='ready'；status 枚举全系统统一为 ready/generating/failed。
7. **参数归一**：result/status 等筛选值 toLowerCase 兼容 'ALL'；分页 size 白名单 10/20/50/100（200/500 本模块数据量小暂不开），默认 10，越界回落默认。
8. 路由声明顺序：字面量路由（screen/review/verify/reminders/reports/generate）必须在 `:id` 之前。

### 3.4 种子数据

新建 `seed-data/ovwr-seed-compliance-v1012.sql`（幂等 ON CONFLICT DO NOTHING，主键用确定性值）：

- nipr_license 10 行：active/expiring/expired/suspended 混合，多州（CA/TX/NY/FL/IL），含 CE 学时数据；channel_id 可空（独立经纪人渠道名用文本）；
- compliance_interception 7 行：blocked/allowed/flagged × high/medium/low，时间分布近 30 天，**含 1 条 blocked 未解决**供 resolve 联调；reasons 用逗号分隔文本、reason_descriptions 对应 jsonb；
- license_expiry_reminder：优先由懒同步生成，另直接插 2 条历史已发送（status=sent）；
- ofac：补 2 条（1 命中 blocked 待复核、1 watchlist）；
- 保留 FT-* 既有行，不删。

执行前先核对 channels 表真实 id（可用则关联，不可用置 NULL）。

## 四、前端改造（web-carrier-admin）

总原则：字段以 API snake_case 为准（视图层直接消费，不另造映射层，与产品/合作模块一致）；文案全部 `t()`；弹窗/按钮/表格向平台既有 class 收敛（btn-primary、glass/glass-strong、data-table 风格、PageLoading、notify('success'|'error')）；弃用 window.confirm/alert。

### 4.1 OFACScreeningView（最重）

- 字段重映射：screening_id / entity_name / entity_type / country（字符串，不 join）/ result / match_score / match_score_level / matched_entry / screened_by / timestamp / reviewed_by / review_date；row key 改 screening_id。
- Quick Screening 表单受控化，提交接 `screenMut.mutateAsync`（screened_by 取当前用户名），成功 toast + invalidate + 展示结果；不再 navigate 跳转。
- watchlist/blocked 行增加「复核」操作：平台标准居中弹窗（reviewed_by/review_note/override_approved + 结论），接 reviewMut；已复核行展示复核结果、操作置灰。
- 筛选/空态/标题硬编码英文全部入 ofac.json（zh/en 对称）。

### 4.2 ComplianceInterceptorView

- 全量字段重映射：interception_id、channel_name、insurer_short、state、line、reasons（文本）、reason_descriptions（jsonb，直接渲染不再用 reasons 索引数组）、severity、action_type、resolved_status、resolved_at、reviewed_by、release_note、timestamp。
- 筛选值改小写 'all'；handleRelease 接 resolveMut（弹窗收集 resolved_status/处理说明，released 为危险放行需二次语义色确认，但非破坏性；escalated/rejected 普通确认）。
- 全页文案从 appointment namespace 迁/补键（本页业务属合规，新增键写入 compliance.json 的 intercept 子树，t 调用同步改 namespace）。

### 4.3 NIPRLicenseCheckView

- 字段重映射：license_id、channel_name、npn_number、license_number、state、license_type、lines(jsonb)、status、expiry_date、last_verified_at、verification_status、ce_hours_required/completed。
- 多选 + 「批量核验」接 verifyMut（{license_ids}）；结果用 notify 逐条/汇总展示（成功 n、失败 n + 原因）；移除 setTimeout 假态与 alert。
- 状态徽标按派生状态（active/expiring/expired/suspended）显示；补 license.json 键。

### 4.4 LicenseExpiryReminderView

- 改用真实字段：reminder_id、days_before、notify_at、status、sent_at、acknowledged_at + JOIN 的 channel_name/license_number/state/license_type/expiry_date。
- severity 前端按 days_before 派生：≤0 overdue(红) / ≤7 high / ≤14 medium / ≤30 low / >30 info；删除服务端不存在的 renewalStatus/lastNotifiedAt 区块（无续期流程端点，按钮置灰或移除，不放假动作）。
- 「知道了」类确认在无后端端点时仅前端本地标记（如保留则明确为本地交互）；本轮以只读列表 + 筛选为主。

### 4.5 ComplianceReportGeneratorView

- 删除内联 mockTemplates/mockReports，接 useReports/useGenerateReport；统计卡由列表真实派生。
- 状态映射：ready → 前端 completed 展示态（文案「已生成」）；generating/failed 原样。
- 新建「生成报告」平台弹窗（report_name/category/period/format/recipients）→ mutation，成功 toast + invalidate；下载在无文件 URL 时置灰并 title 说明；删除假下载。
- 文案键入 compliance.json report 子树（页面 namespace 由 appointment 切到 compliance）。

### 4.6 ComplianceRulesView

- 删除改平台确认弹窗（参照 DisableModal/CooperationDeleteDialog：createPortal、遮罩 blur、danger 红色头部）；
- 创建/编辑/启停成功失败 toast；
- 修复中英串扰：表单中 rule_name / rule_name_en 分别绑定独立字段，按界面语言只展示可编辑对应语言字段时，另一字段保留原值提交（不得用英文值覆盖中文字段）；

### 4.7 ComplianceDashboardView

- recent_alerts 接真实数据（图标/级别按 type+level 映射，点击跳对应列表页并带筛选）；
- 移除假趋势柱值与时间线假事件：有数据源则接（规则 triggered_count 近 6 月趋势可由列表聚合则聚合），无数据源则整块移除，不展示假图；

## 六、验收标准

### 6.1 后端 HTTP 矩阵（带 token）

1. 未带 token 访问各端点 → 401；
2. rules：POST 缺字段/非法枚举 → 400；CRUD + toggle 全通；每次写操作 auth_operation_log 有 COMPLIANCE_RULE_* 记录；
3. ofac：screen 三个已知场景（名单内名称→blocked≥90、模糊→watchlist、普通名→clear）；review 写回 reviewed_by/review_date/override_approved；审计 OFAC_SCREEN/OFAC_REVIEW；
4. interceptions：result 筛选 'ALL'/'all' 等效；resolve 未解决 blocked 记录 → 状态写回 + 审计；
5. licenses：10 条种子可见，状态派生正确；verify 返回逐条结果并更新 last_verified_at；
6. license-reminders：懒同步生成 60/30/7 窗口提醒，重复调用不产生重复行；
7. reports：generate 后 record_count 与真实聚合一致，列表出现新行 status=ready；
8. dashboard：recent_alerts 非空且类型/级别正确。

### 6.2 前端

- 七页面 zh/en 切换无硬编码、无 key 裸露、无白屏；
- OFAC 筛查→列表出现新记录→复核闭环；拦截列表→放行处理闭环；牌照多选→核验闭环；报告生成闭环；规则删除走标准确认弹窗、toast 正确；
- 无 window.confirm/alert/setTimeout 假态；无内联 mock 数据文件被合规视图引用；
- tsc：前端合规相关改动文件零新增类型错误（存量错误不扩面）；后端 tsc --noEmit 通过。

### 6.3 数据与回归

- 联调新增的测试记录在验收后清理（保留种子基线）；FT-* 行不被删除；
- 不触碰 Appointment 4.1–4.4 页面与合作/产品等已验收模块代码。

## 七、风险与约束

- nodemon 热重载 15–40s，HTTP 验证需等待重编译完成；
- ValidationPipe forbidNonWhitelisted 风险：DTO 字段从简，前端多余字段不下发；
- 浏览器 E2E 仅做只读/轻写验证 + HTTP 层验证写操作；**禁止在浏览器里点击最终危险确认按钮做破坏性验证**（上轮误终止合作记录的教训）；
- 种子 SQL 先查后插，channel_id 不可靠时置 NULL；
- 全程不提交 git。
