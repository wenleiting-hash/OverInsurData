## 一、迭代目标

1. **模式 A · SSO 独立入口**：workOS 用户经一次性 code 跳转登录两个子系统，用户与角色由 workOS 单向同步，按既有角色权限体系进入页面。
2. **模式 B · S2S 业务接口**：workOS 后端以 appKey + HMAC 签名调用子系统，完成权限目录获取、用户同步、保单咨询匹配（保司/授权产品/核保要点）三类只读/同步操作。
3. **凭证管理闭环**：子系统管理员可在页面管理接入应用凭证（已先行交付，见第三节）。
4. **联调可验证**：提供 workOS 模拟页（已交付），端到端跑通签名、跳转、同步、查询。

### Phase 1 · 数据模型与 SSO（T1–T2）

#### T1 auth_user 表扩展与迁移

- [ ] 新增 `external_id VARCHAR(64)`，加部分唯一索引 `WHERE deleted = FALSE`（或按现表软删字段调整）

- [ ] 新增种子/迁移脚本 `ovwr-migration-sso-external-id-v1016.sql`，保持幂等（IF NOT EXISTS / DO 块判列存在）

#### T2 SSO 登录链路（后端 + 前端）

- [ ] 后端 `POST /api/auth/sso/exchange`：入参 `{code, state}`；服务端用 client_id/secret 调 workOS W1（URL/凭证走环境变量 `WORKOS_USERINFO_URL` / `WORKOS_CLIENT_ID` / `WORKOS_CLIENT_SECRET`）
- [ ] code → 用户信息 → 按 `external_id` 匹配已同步账号；未匹配返回明确错误码 `SSO_USER_NOT_SYNCED`；禁用返回 `SSO_USER_DISABLED`
- [ ] 匹配成功签发本系统 JWT（access/refresh，复用现有登录响应结构）
- [ ] state 校验（回调页暂存 state，换发时比对；一期可采用随机 state 存 sessionStorage 的轻量方案）
- [ ] 前端新增 `/sso/callback` 独立回调页（提取 code/state → 调 exchange → 存 token → 按角色跳转；失败展示四类错误文案：code 失效/未开通/已停用/安全错误）
- [ ] vite/路由支持 `/sso/callback` 直达（history fallback；回调页在登录守卫白名单内）
- [ ] 登录页"集成平台登录"Tab 重做：仅保留"前往 workOS"说明与跳转按钮（一期 workOS 入口在对方侧，Tab 仅作状态说明），删除 token/user/role 明文参数文档

**验收**：模拟页生成 code 跳转 → 回调页处理 →（W1 真实就绪前可用 mock 开关）进入系统；篡改 role 参数无效；未同步工号被拒。

### Phase 2 · 集成接口（T3–T5）

#### T3 I1 权限目录接口

- [ ] `GET /api/integration/v1/permission-catalog`，挂载 `IntegrationAuthGuard`
- [ ] 复用现有角色/权限表（ovwr-role 相关 service）聚合两个子系统角色：`subsystem_key=carrier_mgmt/channel_mgmt`，输出 role_key、双语名称、描述、权限点、目录 `version`
- [ ] 无分页（目录数据量小）；只读

**验收**：模拟页 I1 Tab 签名调用返回角色清单，role_key 与前端权限管理页一致。

#### T4 I2 用户/角色同步接口

- [ ] `POST /api/integration/v1/users/upsert`，挂载 `IntegrationAuthGuard`
- [ ] 按 `external_id` 幂等 upsert `auth_user`（中英文名/邮箱/部门/状态/来源标记）
- [ ] 角色清单整体替换 `auth_user_role`：校验 `subsystem_key` + `role_key` 必须存在于 T3 目录，非法角色整单拒绝（事务，错误码 `UNKNOWN_ROLE` + invalid_roles）
- [ ] 冲突保护：`auth_method='local'` 同 username/工号冲突返回 `USER_CONFLICT_LOCAL`/`USERNAME_OR_EMAIL_EXISTS`
- [ ] `status=disabled` 拒绝登录（与 T2 联动）；写操作审计（appKey + operator + 工号）

**验收**：同工号重复推送幂等；禁用后无法 SSO 登录；非法角色不落库；模拟页 I2 Tab 全场景通过。

#### T5 I3 保单咨询匹配接口

- [ ] `POST /api/integration/v1/consultation/match`，挂载 `IntegrationAuthGuard`
- [ ] 入参校验：险种枚举、州二字码、customer_type、product_code/keyword 互斥
- [ ] 过滤口径（SQL 聚合 4–5 张表）：合作有效未到期 ∧ 产品已授权接入生效 ∧ 在售 ∧ 该州可售 ∧ 客群匹配

- [ ] 不返回渠道、财务费率、联系人；空结果返回 200 + 空数组
- [ ] 审计：appKey、查询条件、命中数量、耗时落日志/审计表

**验收**：模拟页 I3 Tab 以 AUTO/CA 查询返回真实库数据；终止合作、停售、未开通州均被过滤；响应双语完整。

## 六、关键设计约束（不可回退）

1. 签名串固定为 `METHOD\nPATH\nTIMESTAMP\nNONCE\nSHA256(body)`，与接口文档、模拟页实现三方一致；JSON 请求体发送端须做标准化序列化（模拟页已处理：`JSON.stringify(JSON.parse(text))`），后端验签基于 `JSON.stringify(req.body)`
2. appSecret 仅创建/重置时明文返回一次；库内仅存 AES-GCM 密文
3. SSO 不信任 URL 中的任何身份字段，只认 code 经 W1 换取的服务端结果
4. 同步方向单向 workOS → 子系统；本地账号不受同步接口覆盖
5. I3 不接收/不落客户 PII，不输出渠道与财务数据
6. 三个 v1 接口一律 `IntegrationAuthGuard`，与人工 JWT 完全分离

### 11.7 关键设计决策

1. **subsystem_key 落位 auth_role**：DB 无此概念，T1 加列+回填（`channel_*` → channel_mgmt，余 → carrier_mgmt）。I1 输出按 subsystem_key 分组，I2 校验 (subsystem_key, role_key) 二元组。
2. **W1 联调 mock 方案**：`WORKOS_MOCK=1` + 模拟器在跳转 URL 追加 `&mock_user=base64(json)`；后端 mock 模式直读 mock_user，绕过 W1；生产模式忽略 mock_user。模拟器改动仅在 `genSso()` 拼参数，无新增接口。
3. **/sso/callback 直达**：vite 默认 SPA fallback 让 /sso/callback 返回 index.html；App.tsx 在 `!isAuthenticated` 前插入路径短路，渲染独立 SsoCallbackView（不挂 Layout）。回调成功写 localStorage 后 `window.location.replace('/')` 触发 AuthContext 重新从 localStorage 初始化。
4. **generateTokens 暴露**：AuthService 内私有方法改为 public，SSO 复用同一签发链路（payload 同构）。
5. **T5 customer_type 列**：`insurance_product` 无独立 customer_type 列；本期以 `product_type`/`sub_line` 粗匹配，若 dto.customer_type 与产品 product_type 不一致则过滤；无匹配则不返回该产品（不阻断主链路）。
6. **department 名→code 映射**：I2 dto.department 为中文名，T4 查 auth_department 名匹配；未匹配 dept_code=NULL，不影响 upsert（仅用于展示）。
7. **限流单实例**：内存滑动窗口，预留 Redis 替换点（注释标记），多实例部署前切换。
8. **nonce 清理**：复用已存在 `IntegrationService.cleanupExpiredNonces()`，仅加 cron 触发器。
