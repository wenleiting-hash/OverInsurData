## 一、原型分析摘要

Figma 原型页面采用 **左右分栏 (Master-Detail)** 布局：

- **左侧**：部门树形列表（3 层层级，12 个部门，含展开/折叠、操作菜单 `⋯`）
- **右侧**：选中部门的详情面板（基本信息、负责人卡片、子部门列表、成员表格）
- **顶部**：标题 + 统计卡片（部门总数 / 总成员数 / 最大层级数）+ 搜索框
- **对话框**：新增部门、编辑部门、添加子部门（三者结构一致）、删除确认

### Phase 2 — 后端 API (Department Controller + Service) ✅

**目标**：新建 `DepartmentModule`，提供 6 个 REST 端点

#### 2.1 新建文件清单

| 文件 | 说明 |

| `modules/department/department.controller.ts` | `@Controller('api/departments')` |

| `modules/department/dtos/department.dto.ts` | DTO + class-validator 校验 |

#### 2.2 API 端点

| 方法 | 路径 | 功能 | 权限要求 |
|------|------|------|----------|
| `GET` | `/api/departments/tree` | 返回部门树（含 memberCount） | JWT 认证 |
| `GET` | `/api/departments/:id` | 单个部门详情 + 统计信息 | JWT 认证 |
| `GET` | `/api/departments/:id/members` | 分页获取部门成员列表 | JWT 认证 |
| `POST` | `/api/departments` | 创建部门（含自动生成 dept_code、path） | super_admin / ops_manager |
| `PUT` | `/api/departments/:id` | 更新部门信息 | super_admin / ops_manager |
| `DELETE` | `/api/departments/:id` | 级联软删除部门及子部门 | super_admin / ops_manager |

#### 2.3 关键实现逻辑

| 决策 | 说明 |
|------|------|
| **树形查询** | 分次查询全量节点后在内存中通过 `parent_dept_id` 递归组装树（`buildTree`） |
| **memberCount** | `LEFT JOIN (SELECT dept_code, COUNT(*) FROM auth_user WHERE deleted = FALSE GROUP BY dept_code)` 子查询 |
| **级联删除** | 递归 CTE `getDescendantIds()` 找到所有后代 ID，批量 `SET deleted = TRUE` |
| **循环引用防护** | 编辑时排除自身及其所有后代作为上级部门选项 |
| **自动生成** | `dept_code` 从英文名/中文名大写 + 时间戳后缀生成，`path` 从父级路径拼接 |
| **审计日志** | 所有写操作记录到 `auth_operation_log` 表 |

#### 2.4 注册到 App Module ✅

`app.module.ts` 的 `imports` 中添加 `DepartmentModule`。

#### 5.3 关键 Bug 修复

| Bug | 根因 | 修复 |
|-----|------|------|
| `getDepartmentById` 500 错误 | 子部门查询 `SELECT dept_id, dept_code...` 未加表别名，LEFT JOIN 子查询也有同名列 → `column reference "dept_code" is ambiguous` | 改为 `SELECT d.dept_id, d.dept_code, ...` 加表别名前缀 |
| 种子数据 UNIQUE 冲突 | 旧部门 soft-delete 后 `dept_code` 唯一约束阻止新数据插入 | 硬删旧数据 + `ALTER SEQUENCE RESTART WITH 1` |
| 后端 `tsc` 编译失败 | 3 个预存 TS7016 错误（bcrypt, pg, jsonwebtoken 缺类型声明） | 使用 `ts-node --transpile-only` 直接运行 |

## 五、技术设计决策

| 决策 | 说明 |
|------|------|
| **树形构建策略** | 分次查询全量节点 → 内存中 `buildTree()` 组装（非递归 CTE），降低 PG 复杂度 |
| **主键策略** | `integer dept_id` (SERIAL) 为 PK，`dept_code` (VARCHAR) 为业务标识符 |
| **软删除** | `deleted` boolean 列 + 全局 `WHERE deleted = FALSE` 过滤 |
| **级联删除** | 递归 CTE 收集所有后代 ID → 批量 `SET deleted = TRUE` + 清空关联用户的 `dept_code` |
| **颜色方案** | 8 色预设 `#2563EB #7C3AED #059669 #D97706 #0891B2 #E11D48 #DC2626 #4B5563` |
| **Mock 兜底** | `mockDepartmentTree` 完整 12 部门树，API 不可用时自动降级 |
| **代码分割** | `lazy(() => import('@/views/DepartmentView'))` + Suspense 按需加载 |
