## 一、调整背景

保险公司管理模块重新定位为 **我方纯内部管理**：上游保司均未开放 API，无保司侧用户，数据靠人工录入/文件导入，全域无审批流（登记制 + 审计日志）。

本次迭代基于 **Figma 最新原型**（https://snore-herbs-25374816.figma.site）实测结果，将工程代码对齐原型的 V1.0.1 设计口径。

## 八、业务确认记录（2026-09-15）

业务方就「产品资源接入 / 可售州 / 佣金率归属」确认分层口径：

1. **数据分层**：保险公司（上游主数据/基础数据）→ 产品管理（维护保司产品的属性）→ 合作协议（同一保司在不同州的销售策略、返佣差异）→ 财务结算（引用协议费率对账）。
2. **关联已有产品**：保司详情"关联已有产品"弹窗**仅勾选产品主数据**（名称/代码搜索、批量勾选），不维护可售州/佣金率/生效日期。可售州是产品档案的保司获批州（2.7），列表只读展示；我司实际销售区域与州级返佣由合作关系/协议约定。
3. **佣金率口径（确认保留 D5 主数据 + 新增州维度）**：
   - 佣金率是合作协议（佣金补充协议，3.3）费率条款的**结构化登记镜像**，业务依据以最新生效协议为准；
   - `carrier_commission_rate` 新增 `state varchar(8)` 列（NULL=全域适用）；
   - 对账试算四级回退：**产品+州 → 产品全域 → 险种+州 → 险种全域**，均未配置时沿用导入对账单原值；
   - 不直接采用保司账单金额作为我方期望值（双方数据必须独立，否则差异永远为零）。
4. **实现变更**：migration 增加 state 列与复合索引；CRUD 支持 state（GET 透传、PUT 传 null 可清空）；前端结算比例 Tab 增加"适用州"列与表单项；保司详情新增"关联已有产品"产品勾选弹窗。
