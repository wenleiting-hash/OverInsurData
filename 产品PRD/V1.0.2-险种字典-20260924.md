# 海外保险数字化平台 — 险种字典维护与管理 PRD

**文档版本：** V1.0.2（首版 V1.0.1，本版补充接口明细与矩阵交互）  **创建日期：** 2026-09-24  **文档状态：** 评审稿

**关联文档：** 《技术方案/V1.0.0-系统集成接口文档-20260917.md》（I1–I3 契约基准）

## 1. 背景与目标（摘要）

同一份「业务线→子险种」联动字典目前在后端集成服务、建品表单、联调模拟器三处硬编码；承保范围 9 项全局硬编码且不随业务线联动。本 PRD 将字典入库并提供管理界面与统一接口，三个消费方全部改为动态读取。

**目标：**
1. 三级字典（业务线 / 子险种 / 承保范围）入库，含中英名称、排序、启停。
2. 实现真三级联动：业务线 → 子险种、业务线 → 适用承保范围（关联表驱动）。
3. 消费方（建品表单、集成 match 校验、联调模拟器）动态读取，删除全部硬编码副本。

**非目标：** 不改 I1–I3 既有对外契约与错误码语义；费率因子字典化列为二期。

## 2. 术语

| 术语 | 说明 |
| --- | --- |
| 业务线 Line | 险种大类，如 Auto / Home / Commercial，共 11 个（现网口径） |
| 子险种 Sub Line | 业务线下细分，如 Auto → Personal Auto / Commercial Auto / Fleet Auto |
| 承保范围 Coverage | 产品保障责任项，稳定 key 为 camelCase，如 liability / newCarValue |
| 稳定 key（code） | 字典项的唯一编码，创建后不可修改；产品表（line_of_business / sub_line / coverages）引用它 |
| 归一化别名 | 历史种子数据使用 PascalCase 展示名（如 MedicalPayments），入库后统一 camelCase code，别名表保留为只读兼容层 |

## 4. 数据模型设计

### 4.1 表结构

```sql
-- 业务线
CREATE TABLE IF NOT EXISTS insurance_line (
  id           SERIAL PRIMARY KEY,
  code         VARCHAR(32)  NOT NULL UNIQUE,          -- Auto / Home / ...（不可变）
  name_zh      VARCHAR(64)  NOT NULL,
  name_en      VARCHAR(64)  NOT NULL,
  sort_order   INT          NOT NULL DEFAULT 0,
  status       VARCHAR(16)  NOT NULL DEFAULT 'active', -- active / disabled
  deleted      BOOLEAN      NOT NULL DEFAULT FALSE,
  created_by   VARCHAR(64),
  updated_by   VARCHAR(64),
  created_at   TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
  updated_at   TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

-- 子险种（挂业务线）
CREATE TABLE IF NOT EXISTS insurance_sub_line (
  id           SERIAL PRIMARY KEY,
  line_code    VARCHAR(32)  NOT NULL REFERENCES insurance_line(code),
  code         VARCHAR(64)  NOT NULL,                 -- 'Personal Auto'（含空格与 &，唯一性按 line 维度）
  name_zh      VARCHAR(64)  NOT NULL,
  name_en      VARCHAR(64)  NOT NULL,
  sort_order   INT          NOT NULL DEFAULT 0,
  status       VARCHAR(16)  NOT NULL DEFAULT 'active',
  deleted      BOOLEAN      NOT NULL DEFAULT FALSE,
  created_by   VARCHAR(64),
  updated_by   VARCHAR(64),
  created_at   TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
  updated_at   TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
  UNIQUE (line_code, code)
);

-- 承保范围（全局）
CREATE TABLE IF NOT EXISTS insurance_coverage (
  id           SERIAL PRIMARY KEY,
  code         VARCHAR(64)  NOT NULL UNIQUE,          -- liability / newCarValue（camelCase，不可变）
  name_zh      VARCHAR(64)  NOT NULL,
  name_en      VARCHAR(64)  NOT NULL,
  sort_order   INT          NOT NULL DEFAULT 0,
  status       VARCHAR(16)  NOT NULL DEFAULT 'active',
  deleted      BOOLEAN      NOT NULL DEFAULT FALSE,
  created_by   VARCHAR(64),
  updated_by   VARCHAR(64),
  created_at   TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
  updated_at   TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

-- 业务线 × 承保范围 关联（真三级联动核心）
CREATE TABLE IF NOT EXISTS line_coverage_rel (
  id            SERIAL PRIMARY KEY,
  line_code     VARCHAR(32) NOT NULL REFERENCES insurance_line(code),
  coverage_code VARCHAR(64) NOT NULL REFERENCES insurance_coverage(code),
  created_by    VARCHAR(64),
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (line_code, coverage_code)
);

CREATE INDEX IF NOT EXISTS idx_sub_line_line   ON insurance_sub_line(line_code) WHERE deleted = FALSE;
CREATE INDEX IF NOT EXISTS idx_rel_line        ON line_coverage_rel(line_code);
```

**设计要点：**
1. `code` 一律不可变：更新接口仅接受 name_zh / name_en / sort_order / status。
2. 删除为软删（deleted=TRUE）；被产品引用的项在应用层拒绝删除（见 6.4 引用统计）。
3. 子险种 `code` 保留原始形态（'Personal Auto'、'D&O'），与产品表 sub_line 现存值一致，避免数据迁移。
4. 业务线 `code` 大小写敏感统一为现网 PascalCase（Auto / D&O / E&O），match 校验沿用现有 canonical 归一化。

## 6. 接口设计

后端新增 `modules/dictionary`（controller / service / module），路径前缀 `/api/dictionaries`。除 coverage-tree 外均需 `dict:manage` 权限。

### 6.1 业务线

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/dictionaries/lines` | 列表：全字段 + sub_line_count + product_count（deleted=false 口径），支持 `?includeDisabled=true` |
| POST | `/api/dictionaries/lines` | 新增：`{code, nameZh, nameEn, sortOrder}`；code 全局唯一、格式 `^[A-Z][A-Za-z&]{1,31}$` |
| PUT | `/api/dictionaries/lines/:code` | 更新：仅 nameZh / nameEn / sortOrder（code 不可变） |
| PUT | `/api/dictionaries/lines/:code/status` | 启停：`{status}`；停用前校验引用并返回影响数（见 6.4） |
| DELETE | `/api/dictionaries/lines/:code` | 软删；被产品引用（line_of_business）或存在子险种时 409 |

### 6.2 子险种

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/dictionaries/lines/:lineCode/sub-lines` | 该业务线下子险种列表 + product_count |
| POST | `/api/dictionaries/lines/:lineCode/sub-lines` | 新增：`{code, nameZh, nameEn, sortOrder}`；(line_code, code) 唯一 |
| PUT | `/api/dictionaries/sub-lines/:id` | 更新：nameZh / nameEn / sortOrder |
| PUT | `/api/dictionaries/sub-lines/:id/status` | 启停 |
| DELETE | `/api/dictionaries/sub-lines/:id` | 软删；被产品引用（sub_line）时 409 |

### 6.3 承保范围与关联

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/dictionaries/coverages` | 全局列表 + product_count（coverages JSONB 包含统计） |
| POST | `/api/dictionaries/coverages` | 新增：code 格式 `^[a-z][a-zA-Z]{2,63}$`（camelCase） |
| PUT | `/api/dictionaries/coverages/:code` | 更新：nameZh / nameEn / sortOrder |
| PUT | `/api/dictionaries/coverages/:code/status` | 启停 |
| DELETE | `/api/dictionaries/coverages/:code` | 软删；被产品引用或存在关联时 409 |
| GET | `/api/dictionaries/lines/:lineCode/coverages` | 该业务线已勾选的 coverage code 列表 |
| PUT | `/api/dictionaries/lines/:lineCode/coverages` | 全量替换勾选：`{coverageCodes: string[]}`；取消勾选不校验产品存量（见 8.3 兼容策略） |

### 6.4 引用统计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/dictionaries/:type/:key/usage` | `type ∈ {line, sub-line, coverage}`；返回 `{productCount, subLineCount?}`，用于删除/停用确认框 |

统计口径（现网数据真实分布，注意大小写）：产品 `line_of_business` 与 `sub_line` 为精确匹配；`coverages` JSONB 数组按「小写化 + 别名归一化」后匹配 code。

### 6.5 联动树（消费方统一入口）

`GET /api/dictionaries/coverage-tree`（登录态，无需 dict:manage）

```json
{
  "success": true,
  "data": {
    "version": "2026-09-24T08:00:00Z",
    "lines": [
      {
        "code": "Auto", "nameZh": "车险", "nameEn": "Auto", "sortOrder": 1,
        "subLines": [ { "code": "Personal Auto", "nameZh": "个人车险", "nameEn": "Personal Auto", "sortOrder": 1 } ],
        "coverages": [ { "code": "liability", "nameZh": "责任险", "nameEn": "Liability", "sortOrder": 1 } ]
      }
    ],
    "allCoverages": [ { "code": "liability", "nameZh": "责任险", "nameEn": "Liability", "sortOrder": 1 } ]
  }
}
```

- 默认仅返回 `status='active'` 且 `deleted=false`，按 sort_order 升序。
- `allCoverages` 供管理矩阵与「业务线未配置关联时兜底展示」使用。
- `version` 为该缓存快照生成时间，供模拟器展示数据新鲜度。

### 6.6 集成侧字典快照（新增 I4）

`GET /api/integration/v1/insurance-catalog`（复用 IntegrationAuthGuard 签名鉴权）

返回结构与 6.5 一致（外层 `success/data`），额外含 `catalogVersion`。供联调模拟器与外部调用方做前置校验；**I1–I3 路径、请求、响应、既有错误码完全不变**。

### 6.7 错误码汇总

| 错误码 | HTTP | 场景 |
| --- | --- | --- |
| DICT_CODE_EXISTS | 409 | code 重复（业务线全局 / 子险种按线 / coverage 全局） |
| DICT_CODE_IMMUTABLE | 400 | 请求试图修改 code |
| DICT_LINE_NOT_FOUND / DICT_SUB_LINE_NOT_FOUND / DICT_COVERAGE_NOT_FOUND | 404 | 目标不存在或已删除 |
| DICT_IN_USE | 409 | 删除被引用项：`{productCount, subLineCount}` 明细返回 |
| DICT_INVALID_CODE_FORMAT | 400 | code 格式不符合规范 |
| INVALID_COVERAGES_FOR_LOB | 400 | **集成 match 新增**：提交的 coverages 不在该业务线适用范围（返回 `invalid_coverages` 明细，风格对齐 I3 既有 `INVALID_SUB_LINE_FOR_LOB`） |

## 7. 管理界面设计

### 7.1 入口与布局

- 菜单：系统管理 → **险种字典管理**（i18n 命名空间 `dict.json`，zh/en 对称，键前缀 `dict.`）。
- 页内 3 个 Tab：**业务线与子险种**｜**承保范围**｜**适用范围矩阵**。

### 7.2 Tab1 业务线与子险种（左右分栏）

- **左栏**：业务线列表（中文名 + code + 状态徽标；active 在前，按 sort_order）；顶部「+ 新增业务线」按钮（弹窗：code/中文/英文/排序）。
- **右栏**（选中业务线）：
  - 基本信息卡：中英名称行内编辑、排序调整（上移/下移）、启用停用开关、删除按钮（引用 >0 时禁用并悬浮提示原因）。
  - 子险种表：列 = code / 中文名 / 英文名 / 排序 / 状态 / 关联产品数 / 操作（编辑、启停、删除、上移下移）；「+ 新增子险种」按钮。
- 删除/停用确认框统一展示「关联产品 N 个」，N>0 时删除按钮禁用、停用需勾选「我已知悉影响」。

### 7.3 Tab2 承保范围

- 全局表格：code / 中文名 / 英文名 / 排序 / 状态 / 关联产品数 / 操作；「+ 新增承保范围」（弹窗：code camelCase、双语名、排序）。
- 行内操作同 Tab1；code 不可编辑。

### 7.4 Tab3 适用范围矩阵

- 表格：行 = 业务线（按 sort_order），列 = 承保范围（按 sort_order，可横向滚动），单元格 = checkbox。
- 行尾「已选 N/9」汇总列；支持按行快速「全选/清空」。
- 保存：每行独立「保存」或右上「全部保存」（全量替换该行关联，调 6.3 PUT）。
- 取消勾选时若该业务线在售产品已引用该 coverage，行内黄条提示「N 个产品正在使用，取消后新建产品不可再选，存量产品不受影响」（见 8.3）。
- 变更写审计。

### 7.5 交互细节

- 所有列表支持中英名称随界面语言切换展示。
- 空态：业务线无子险种时显示引导文案「为该业务线添加第一个子险种」。
- 写操作成功后 toast + 列表刷新；接口错误按错误码映射文案（DICT_CODE_EXISTS → 「编码已存在」等）。

## 8. 消费方改造明细

### 8.1 ProductForm（建品/编辑表单）

1. 进入表单时并行拉取 `GET /api/dictionaries/coverage-tree`（react-query 缓存，TTL 5 分钟 + 手动失效）。
2. 业务线下拉 → 子险种下拉联动：数据源由本地 SUB_LINE_MAP 改为 `tree.lines[].subLines`；**删除本地 SUB_LINE_MAP 常量**。
3. 承保范围多选：选项 = `tree.lines[当前业务线].coverages`（真三级联动）；未配置关联的业务线兜底展示 `allCoverages`。
4. 选项标签：优先接口 nameZh/nameEn；接口无值时回退 i18n `detail.info.*`。
5. 编辑回填兼容：产品已存的 sub_line / coverages 若不在当前 active 集合（已停用/已删除），仍回显原值，选项尾部追加「（已停用）」置灰标记，不可新增选择但保留提交，避免保存时静默清空。

### 8.2 integration.service（I3 match 校验）

1. 启动时加载字典快照至进程内缓存：`{ subLineMap, coverageSet, lineCoverageMap }`；dictionary 模块任一写操作后调用缓存失效（同进程直接失效；预留跨实例事件接口）。
2. `sub_line` 校验：逻辑不变（canonical lob → 子险种集合比对），数据源改缓存；`INVALID_SUB_LINE_FOR_LOB` 错误码与响应结构不变。
3. `coverages` 校验：归一化后先比对全局 coverageSet（未知项仍报 `INVALID_COVERAGES`），再按 lineCoverageMap 校验业务线适用性，不适用项报 **`INVALID_COVERAGES_FOR_LOB`**（新增错误码，需同步更新集成接口文档附录）。
4. `COVERAGE_ALIASES` / `FACTOR_ALIASES` 保留为只读兜底（历史种子数据 PascalCase 兼容），不提供界面维护。
5. 产品匹配过滤（SUB_LINE_MISMATCH 扣分逻辑）数据源同步改缓存，评分行为不变。

### 8.3 存量数据兼容策略

| 场景 | 策略 |
| --- | --- |
| 产品引用的字典项被停用 | 表单回显置灰「（已停用）」；详情页正常展示；match 校验对存量产品的 sub_line/coverages 比对**不受停用影响**（停用仅约束新建） |
| 产品引用的字典项被软删 | 表单同样回显；match 按未知值处理（与现状一致） |
| 业务线关联被取消勾选 | 仅约束新建/编辑时新增选项；存量产品 coverages 不改动；match 校验同样不追溯存量 |
| 历史别名（PascalCase） | 别名归一化层永久保留，仅代码内维护 |

### 8.4 联调模拟器（workos-simulator.html）

1. 页面加载时调用 `GET /api/integration/v1/insurance-catalog`（带签名头；鉴权失败或超时 3s 降级）。
2. 子险种下拉、产品维度过滤区随返回数据渲染；顶部显示「字典版本 catalogVersion + 拉取时间」，提供「刷新字典」按钮。
3. **删除内置 SUB_LINE_MAP 联动依赖**，仅保留一份只读降级快照（注释标明「降级兜底，非数据源」）。
4. 承保范围过滤区（如模拟器含该控件）同步改按业务线联动。

## 9. 数据迁移方案

- 迁移文件：`seed-data/ovwr-migration-insurance-dict-v1018.sql`（版本号以实际迭代序列为准）。
- 内容：4.1 四表 DDL（幂等 IF NOT EXISTS）+ 4.2 播种（ON CONFLICT DO NOTHING，可重复执行）。
- 上线顺序：**先执行迁移 → 再发后端 → 再发前端**（字典就绪后消费方才切换数据源，任一顺序错乱均有硬编码兜底，不会白屏）。
- 回滚：迁移仅新增表，不触碰既有表；回滚后端镜像即恢复硬编码口径，字典表可保留。

## 10. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | coverage-tree P95 < 100ms（进程内缓存命中路径）；管理列表 < 500ms |
| 缓存 | 管理端任一写操作后缓存立即失效；coverage-tree version 更新；模拟器展示版本可感知 |
| 审计 | 复用 audit.service：对象类型 dict_line / dict_sub_line / dict_coverage / dict_line_coverage_rel；记录操作人、时间、变更前后 JSON |
| 安全 | 管理接口走现有 JWT + 权限点；集成快照走 IntegrationAuthGuard 签名 + nonce 防重放（与 I1–I3 一致） |
| i18n | 新增 dict.json 命名空间（zh/en 对称）；0 raw key 泄露 |
