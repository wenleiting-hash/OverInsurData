### 2.2 请求链路

- 浏览器 → `http://220.154.128.28:8601` → Nginx
- 页面/静态资源：Nginx 直接返回 `/opt/overinsur/deploy/web` 下文件，未知路径回退 `index.html`（SPA history 模式）
- 接口调用：`/api/*` 由 Nginx 反代到 `127.0.0.1:8610`（carrier-api 容器内 8080）
- 文件访问：`/uploads/*` 同样反代到 carrier-api，文件实体存于挂载目录

## 3. Docker 服务

### 3.1 本系统容器

| 容器名 | 镜像 | 端口映射 | 状态策略 | 说明 |
| --- | --- | --- | --- | --- |
| `carrier-api` | `overinsur-carrier-api:latest` | `127.0.0.1:8610 → 8080` | unless-stopped，带 healthcheck（healthy） | 后端 API，NestJS |
| `overinsur-pg` | `postgres:16` | `127.0.0.1:5460 → 5432` | unless-stopped | PostgreSQL 16.14 |

两容器同属 bridge 网络 `overinsur-net`，后端通过容器名 `overinsur-pg:5432` 访问数据库。

### 3.2 编排文件

- Compose 文件：`/opt/overinsur/docker-compose.yml`
- 环境变量：`/opt/overinsur/.env`（权限 600，含 DB/JWT/集成密钥明文，**不进代码仓库、禁止外发**）
- 数据卷：命名卷 `overinsur-pg-data`（PG 数据）；bind mount `/opt/overinsur/data/uploads → /app/uploads`

### 3.3 常用运维命令

```bash
cd /opt/overinsur

docker compose ps                 # 查看两容器状态
docker compose logs -f carrier-api   # 跟踪后端日志
docker compose restart carrier-api   # 重启后端（代码未变时）
docker compose up -d carrier-api     # 应用镜像/配置变更后重建容器
docker compose build carrier-api     # 基于 /opt/overinsur/src 源码重新构建镜像
```

## 6. Nginx 配置

配置文件：`/etc/nginx/conf.d/overinsur.conf`（8601 专用，与宿主机其他站点隔离）。

关键规则：

| 配置项 | 值 / 规则 |
| --- | --- |
| listen | `8601` |
| root | `/opt/overinsur/deploy/web` |
| client_max_body_size | `25m`（文件上传） |
| SPA 回退 | `try_files $uri $uri/ /index.html` |
| `/api/` | proxy_pass → `http://127.0.0.1:8610`（透传 Host / X-Real-IP / X-Forwarded-*） |
| `/uploads/` | proxy_pass → `http://127.0.0.1:8610` |
| gzip | 开启（text/css / application/javascript / application/json，>1KB） |

修改配置后：`nginx -t && nginx -s reload`。

## 10. 备份与恢复（现状）

### 10.1 已落实

- **前端**：每次发布前手工 tar 全量备份 `web/`，保存在 `/opt/overinsur/deploy/web-backup-*.tar.gz`。
- **后端源码**：涉及后端的发布前手工备份被覆盖文件（如 V1.0.2 备份于 `/tmp/dict-bak/`，注意 `/tmp` 重启可能清空）。
- **上传文件**：bind mount 持久化于宿主机 `/opt/overinsur/data/uploads`（容器重建不丢）。
- **数据库**：PG 数据在命名卷 `overinsur-pg-data`，容器删除不影响数据。

### 10.2 待落实（风险项）

- **数据库尚未配置定时备份**（实测 root crontab 无 overinsur/pg_dump 任务），`/opt/overinsur/backup` 目录为空。建议尽快建立：

```bash
# 建议的每日 02:30 逻辑备份（保留 7 天），加入 crontab：
30 2 * * * docker exec overinsur-pg pg_dump -U overinsur overinsur_db \
  | gzip > /opt/overinsur/backup/overinsur_db_$(date +\%Y\%m\%d).sql.gz \
  && find /opt/overinsur/backup -name 'overinsur_db_*.sql.gz' -mtime +7 -delete
```

### 10.3 手工备份/恢复命令

```bash
# 手工全量备份
docker exec overinsur-pg pg_dump -U overinsur overinsur_db | gzip > /opt/overinsur/backup/manual_$(date +%F).sql.gz

# 恢复（谨慎，会覆盖同名表数据）
gunzip -c /opt/overinsur/backup/xxx.sql.gz | docker exec -i overinsur-pg psql -U overinsur -d overinsur_db

# 前端回滚
cd /opt/overinsur/deploy && rm -rf web && mkdir web && \
  tar -xzf web-backup-<日期>.tar.gz -C web --strip-components=1
```

数据库迁移类发布遵循「只增不改」原则，不做数据库回滚；后端可回滚镜像/源码，字典等新增表对旧代码无害。

## 11. 安全注意事项

1. 对外仅开放 TCP 8601（天翼云安全组）；8610（API）、5460（PG）严格绑定 127.0.0.1，不经公网。
2. 服务器为多租户共享宿主机，变更 Docker/Nginx 全局配置前须确认不影响其他项目容器。
3. 集成接口（I1–I4）采用 appKey + HMAC-SHA256 签名 + 时间戳（±300 秒）+ nonce 防重放 + IP 白名单；appSecret 仅创建/重置时展示一次。
4. 管理端使用 JWT（Access/Refresh 双令牌）+ RBAC 权限点（如 `dict:read` / `dict:manage`）。
5. `.env` 与生产 appSecret 严禁写入代码、文档、前端页面或聊天工具；模拟器中预填的仅为**本地开发**凭证，不适用于生产。
6. 默认管理员密码 `admin123` 应修改；SSH 建议改用密钥登录并禁用密码登录（首版计划项，待确认落实）。

## 12. 常见问题速查

| 现象 | 排查方向 |
| --- | --- |
| 公网打不开 8601 | 天翼云安全组是否放行 TCP 8601；`ss -tlnp | grep 8601`；`systemctl status nginx` |
| 页面 502/接口报错 | `docker compose ps` 看 carrier-api 是否 healthy；`docker compose logs --tail=100 carrier-api` |
| 容器一直 starting/不健康 | 后端连不上 DB：确认 overinsur-pg 已起、`.env` 中 DB 密码与库一致 |
| 接口 401 INVALID_SIGNATURE | 集成请求签名串/时间戳/nonce 错误，或 app 已停用（管理端鉴权失效也返回此码） |
| 上传失败/413 | Nginx `client_max_body_size 25m` 限制，超限需调大并 reload |
| 前端更新后仍是旧页 | 构建产物文件名带 hash，强刷浏览器缓存；确认 index.html 引用的 asset 在 `web/assets/` 中存在 |
| 磁盘上涨 | 排查 Docker：`docker system df`；清理悬挂镜像 `docker image prune`（避开其他项目镜像） |
