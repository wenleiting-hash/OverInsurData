## 3. 快速启动命令

### 3.1 Windows PowerShell 一键启动脚本

**文件位置**: `scripts/start-test-env.ps1`

```powershell
#!/usr/bin/env pwsh
# Test Environment Starter for InsureOS Platform
# Version: 1.0
# Date: 2026-09-04

$ErrorActionPreference = "Stop"

# Colors for output
$GREEN = [ConsoleColor]::Green
$RED = [ConsoleColor]::Red
$YELLOW = [ConsoleColor]::Yellow
$BLUE = [ConsoleColor]::Blue

Write-Host "=====================================" -ForegroundColor $BLUE
Write-Host "  InsureOS 测试环境启动脚本 v1.0" -ForegroundColor $BLUE
Write-Host "=====================================" -ForegroundColor $BLUE
Write-Host ""

# Check Node version
Write-Host "[Step 1/6] Checking Node.js version..." -ForegroundColor Yellow
$nodeVersion = & node -v 2>&1
if ($LASTEXITCODE -ne 0) {
    Write-Host "❌ Node.js is not installed!" -ForegroundColor Red
    exit 1
}
Write-Host "✓ Node.js version: $nodeVersion" -ForegroundColor $GREEN

# Install dependencies
Write-Host ""
Write-Host "[Step 2/6] Installing dependencies..." -ForegroundColor Yellow
cd "$PSScriptRoot/../insurance-platform"

if (-not (Test-Path "node_modules")) {
    Write-Host "Installing with pnpm..." -ForegroundColor $YELLOW
    pnpm install
    if ($LASTEXITCODE -ne 0) {
        Write-Host "Failed to install dependencies!" -ForegroundColor Red
        exit 1
    }
} else {
    Write-Host "✓ Dependencies already installed" -ForegroundColor $GREEN
}

# Build carrier service
Write-Host "" 
Write-Host "[Step 3/6] Building Carrier Service..." -ForegroundColor Yellow
cd "../insurance-platform/apps/carrier-service"
if (-not (Test-Path "dist")) {
    Write-Host "Building TypeScript..." -ForegroundColor $YELLOW
    pnpm run build
    if ($LASTEXITLINE -ne 0) {
        Write-Host "Failed to build carrier service!" -ForegroundColor Red
        exit 1
    }
    Write-Host "✓ Carrier Service built successfully" -ForegroundColor $GREEN
} else {
    Write-Host "✓ Dist folder exists, skipping build" -ForegroundColor $GREEN
}

# Start services in parallel
Write-Host "" 
Write-Host "[Step 4/6] Starting services..." -ForegroundColor Yellow

$carrierServiceStart = Start-Process powershell -ArgumentList "-NoExit","-Command","cd '$PSScriptRoot/../insurance-platform/apps/carrier-service'; pnpm run dev" -PassThru
Write-Host "✓ Carrier Service starting on http://localhost:8080" -ForegroundColor $GREEN

# Wait a bit for backend
Write-Host "Waiting for Carrier Service to start..." -ForegroundColor $YELLOW
Start-Sleep -Seconds 8

$frontEndStart = Start-Process powershell -ArgumentList "-NoExit","-Command","cd '$PSScriptRoot/../insurance-platform/apps/web-carrier-admin'; pnpm run dev" -PassThru
Write-Host "✓ Frontend starting on http://localhost:3001" -ForegroundColor $GREEN

Write-Host ""
Write-Host "=====================================" -ForegroundColor $GREEN
Write-Host "  ✅ 测试环境启动成功！" -ForegroundColor $Green
Write-Host "=====================================" -ForegroundColor $GREEN
Write-Host ""
Write-Host "访问地址:" -ForegroundColor Cyan
Write-Host "  🌐 Frontend: http://localhost:3001" -ForegroundColor White
Write-Host "  🔧 Backend:  http://localhost:8080" -ForegroundColor White
Write-Host ""
Write-Host "默认账户：" -ForegroundColor Cyan
Write-Host "  👤 Username: admin" -ForegroundColor White
Write-Host "  🔑 Password: admin123" -ForegroundColor White
Write-Host ""
Write-Host "按任意键查看日志窗口..." -ForegroundColor Yellow
[Console]::ReadKey($true) | Out-Null
```

## 6. 常见问题排查

### 6.1 端口冲突

**问题**: `Port 3001 is already in use`

**解决方案**:
```powershell
# 查找占用端口的进程 ID
Get-NetTCPConnection -LocalPort 3001 | Select-Object Owner

# 终止进程（替换 <PID> 为实际进程 ID）
taskkill /F /PID <PID>
```

### 6.2 依赖安装失败

**问题**: `pnpm install` 报 Network timeout

**解决方案**:
```powershell
# 切换镜像源
pnpm config set registry https://registry.npmmirror.com

# 清理缓存后重新安装
pnpm store cleanup
rm -r node_modules
pnpm install
```

### 6.3 前端无法访问后端

**问题**: CORS 错误或网络请求失败

**检查项**:
1. 确认后端服务已启动 (`http://localhost:8080`)
2. 检查 `web-carrier-admin/vite.config.ts` 代理配置
3. 查看浏览器 Console 的错误详情

### 6.4 后端类型编译错误

**问题**: `TypeScript compilation failed`

**解决方案**:
```powershell
cd insurance-platform\apps\carrier-service

# 清理编译产物
cd services\carrier-service
Remove-Item -Recurse -Force dist

# 重新编译
pnpm run build
```

## 8. 附录：故障恢复方案

### 8.1 完全重装依赖

**当依赖混乱导致无法启动时**

```powershell
cd insurance-platform

# 1. 删除所有 node_modules 和锁文件
Remove-Item -Recurse -Force node_modules
Remove-Item -Force pnpm-lock.yaml

# 2. 清理 pnpm 存储
pnpm store cleanup

# 3. 全新安装
pnpm install

# 4. 分别启动各服务
# ❌ 旧路径已废弃：cd services/carrier-service
# ✅ 新路径（NestJS Workspace）:
cd insurance-platform\apps\carrier-service
pnpm run build
cd ../insurance-platform/apps/web-carrier-admin
```

### 8.2 重置本地数据库（如果使用 SQLite）

**当数据损坏需要重置时**

```powershell
# 找到数据库文件（通常在 insurance-platform/apps/carrier-service/data/）
cd insurance-platform\apps\carrier-service
Remove-Item -Force data/*.sqlite

# 重启服务，Drizzle 会自动重建 schema
```

### 8.3 回滚到已知可用的 Git Commit

**当最近修改导致问题时**

```powershell
# 查看提交历史
git log --oneline -10

# 回退到指定 commit
git reset --hard <commit-hash>

# 强制推送到远程（谨慎操作）
git push --force
```

## 9. API 接口测试指南

### 9.1 Swagger UI 在线文档

后端内置 Swagger 文档，启动后浏览器访问：

```
http://localhost:8080/api
```

> 支持在线查看所有接口定义、参数 Schema、响应结构，并可直接在页面内发送请求调试。点击右上角 **Authorize** 按钮输入 Bearer Token 后即可在线测试需要认证的接口。

### 9.2 认证流程

所有业务接口均需 JWT Bearer Token 认证。登录获取 Token：

```powershell
# PowerShell 方式
$login = Invoke-RestMethod -Uri http://localhost:8080/api/auth/login `
  -Method Post -ContentType 'application/json' `
  -Body '{"username":"admin","password":"admin123"}'

# Token 在 data.accessToken 层级下
$token = $login.data.accessToken
$refreshToken = $login.data.refreshToken

# 后续请求统一携带 Token
$h = @{ Authorization = "Bearer $token" }
```

```bash
# curl 方式（CMD / Git Bash）
curl -s -X POST http://localhost:8080/api/auth/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"admin\",\"password\":\"admin123\"}"
```

**Token 有效期**：约 1 小时（JWT_EXPIRATION=15m 为 access token，refresh token 7 天）。过期后接口返回 401，需用 refresh token 刷新或重新登录。

```powershell
# 刷新 Token
$refresh = Invoke-RestMethod -Uri http://localhost:8080/api/auth/refresh `
  -Method Post -ContentType 'application/json' `
  -Headers @{ Authorization = "Bearer $refreshToken" }
$newToken = $refresh.data.accessToken
```

#### 9.8.3 HMAC-SHA256 签名算法

每次请求需携带以下 4 个请求头：

| 请求头 | 说明 | 示例 |
|--------|------|------|
| `x-app-key` | 应用 appKey | `ak_2f8b...` |
| `x-timestamp` | 当前 Unix 秒时间戳（±300 秒内有效） | `1789715526` |
| `x-nonce` | 唯一随机字符串（防重放，同一 appKey 不可重复） | `a1b2c3d4e5f6...` |
| `x-signature` | HMAC-SHA256 签名 hex 小写 | `e3b0c44298...` |

**签名计算步骤**：

```
1. 构造请求体 JSON 字符串（GET 请求为空字符串）
   bodyStr = JSON.stringify(requestBody)  // 或 ""

2. 计算请求体的 SHA-256 哈希（hex 小写）
   bodyHash = SHA256(bodyStr)

3. 构造签名串（5 行，用 \n 分隔）
   signatureString = HTTP_METHOD + "\n"
                   + 请求路径(含query, 如 /api/integration/v1/permission-catalog) + "\n"
                   + timestamp + "\n"
                   + nonce + "\n"
                   + bodyHash

4. 使用 appSecret 作为密钥计算 HMAC-SHA256
   signature = HMAC_SHA256(appSecret, signatureString)
   输出为 hex 小写字符串
```

**安全机制**：
- 时间戳 ±300 秒窗口，超出返回 `TIMESTAMP_EXPIRED`
- nonce 防重放，同一 appKey 的 nonce 不可重复
- IP 白名单（配置后生效，支持 CIDR）
- 限流：按 appKey 滑动窗口 60 秒内不超过 `rate_limit` 次（默认 60）
- 签名不匹配时后端日志会打印完整诊断信息（method/url/bodyHash/签名串/期望签名），便于客户端联调

#### 9.8.4 PowerShell 模拟外部系统调用

**GET 请求示例**（权限目录）：

```powershell
$appKey = "你的appKey"
$appSecret = "你的appSecret"

$method = "GET"
$path = "/api/integration/v1/permission-catalog"
$timestamp = [string][int](Get-Date -UFormat %s)
$nonce = [guid]::NewGuid().ToString("N")
$bodyStr = ""

# SHA-256(body)
$bodyHash = [System.BitConverter]::ToString(
  [System.Security.Cryptography.SHA256]::Create().ComputeHash(
    [System.Text.Encoding]::UTF8.GetBytes($bodyStr)
  )
).Replace("-", "").ToLower()

# 签名串
$sigString = "$method`n$path`n$timestamp`n$nonce`n$bodyHash"

# HMAC-SHA256
$hmac = [System.Security.Cryptography.HMACSHA256]::new()
$hmac.Key = [System.Text.Encoding]::UTF8.GetBytes($appSecret)
$signature = [System.BitConverter]::ToString(
  $hmac.ComputeHash([System.Text.Encoding]::UTF8.GetBytes($sigString))
).Replace("-", "").ToLower()

# 发送请求
$result = Invoke-RestMethod -Uri "http://localhost:8080$path" -Method Get -Headers @{
  "x-app-key"     = $appKey
  "x-timestamp"   = $timestamp
  "x-nonce"       = $nonce
  "x-signature"   = $signature
}
Write-Output ($result | ConvertTo-Json -Depth 10)
```

#### 9.8.5 签名校验失败的排查

后端签名校验失败时会在日志中打印诊断信息，包含：
- `method` / `url` — 实际收到的请求方法和路径
- `bodyStr` / `bodyHash` — 请求体原文和哈希
- `signatureString` — 完整签名串（5 行）
- `expected(plainSecret)` — 后端计算的期望签名
- `actual` — 客户端发送的签名

**常见原因**：
1. **请求体不一致**：签名时用的 bodyStr 与实际发送的 body 不同（如 JSON 序列化方式差异）
2. **路径不含 query**：签名串中的路径应包含 query string（如 `/api/integration/v1/catalog?type=all`）
3. **appSecret 错误**：使用了已重置的旧 secret（重置后旧 secret 立即失效）
4. **时间戳过期**：客户端与服务器时间差超过 300 秒
5. **nonce 重复**：同一 appKey 的 nonce 被复用
