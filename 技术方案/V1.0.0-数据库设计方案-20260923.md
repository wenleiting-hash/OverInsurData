### 1.3 命名规范

| 约定 | 说明 |
|---|---|
| 无前缀业务表 | `auth_*`、`carrier_*`、`insurance_*`、`channel_*` — 后端直接 SQL 查询的核心表 |
| `ovwr_` 前缀表 | i18n/字典/权限模板 — Drizzle schema 定义，后端通过 ORM 访问 |
| 主键 | 业务表用 `{domain}_id VARCHAR(32)`；auth 基础表用 integer SERIAL + `user_uuid VARCHAR(36)` 双键 |
| 外键 | 显式 FK constraint（`REFERENCES insurance_carrier(carrier_id) ON DELETE CASCADE`） |
| 软删除 | `deleted BOOLEAN NOT NULL DEFAULT FALSE`，后端查询统一带 `WHERE deleted = FALSE` |

### 2.3 产品域（insurance_product + 5 张 product_*）

- **insurance_product**（~40 列）：产品主表，含险种、州可用性、承保范围 JSON、核保要点 JSON、费率/业绩聚合字段；FK → insurance_carrier(carrier_id) ON DELETE CASCADE
- **product_state**（~10 列）：产品州可用性授权，主键 (product_id, state_code)
- **product_rate_plan**（~12 列）：费率计划
- **product_underwriting_rule**（~14 列）：核保规则
- **product_training_material**（~12 列）：培训材料
- **product_performance**（~12 列）：业绩指标（按月聚合）

### 2.4 合作域（carrier_* 7 张）

- **carrier_partnership**（~25 列）：合作关系主表，含状态、pending_change JSON（状态变更审批）
- **carrier_contract**：合同信息
- **carrier_contact**：联系人
- **carrier_settlement_config**：结算配置
- **carrier_renewal_task**：续约任务（含 registered_at/registered_by/new_expiry_date 等补列）
- **carrier_product_access_request**：产品接入申请
- **carrier_commission_rate**：佣金率

### 2.5 财务结算域（9 张）

- **commission_bill** / **commission_bill_line**：佣金账单 + 明细行（含 import_stats/mapping_template_id 等补列、line_status 列）
- **commission_statement** / **commission_statement_line**：对账单 + 明细
- **reconciliation_diff**（~15 列）：对账差异（含 resolution_result/follow_ups/suspend_reason 等补列）
- **reconciliation_run**：对账批次运行
- **settlement_cycle_config**：结算周期配置
- **insurer_finance_profile**（~15 列）：保司财务画像（含 auto_reconcile/bank_account/routing_number 等补列）
- **bill_field_mapping_template**：账单字段映射模板

### 2.6 集成与渠道域（12 张）

渠道资质（nipr_license, license_expiry_reminder）、合规（ofac_screening_record, compliance_rule/audit_report/interception）、合作产品目录（cooperation_product）、集成应用（integration_app, integration_nonce）。

### 2.7 i18n/字典域（ovwr_* 4 张）

- **ovwr_auth_i18n_translation**（~15 列）：i18n 词条表（双语文本 + module/section 分组 + review 状态）
- **ovwr_dict_term**：字典项
- **ovwr_user_preferences**（8 列）：用户偏好（语言/日期格式/时区/主题）—— 修复语言持久化的关键表
- **ovwr_auth_permission_template**（~15 列）：权限模板（ovwr_format/ovwr_permissions/ovwr_metadata 等）

## 五、生产部署与备份策略

### 5.1 容器配置

```yaml
# /opt/overinsur/docker-compose.yml
overinsur-pg:
  image: postgres:16
  container_name: overinsur-pg
  restart: unless-stopped
  environment:
    POSTGRES_DB: overinsur_db
    POSTGRES_USER: overinsur
    POSTGRES_PASSWORD: ${DB_PASSWORD}  # 强密码，仅在 .env
  ports:
    - "127.0.0.1:5460:5432"           # 不对公网
  volumes:
    - overinsur-pg-data:/var/lib/postgresql/data
    - /opt/overinsur/backup:/backup
  mem_limit: 512m
  networks: [overinsur-net]
```

### 5.2 备份

```bash
# 每日 02:30 全量，保留 7 天
0 30 * * * docker exec overinsur-pg pg_dump -U overinsur overinsur_db | \
  gzip > /opt/overinsur/backup/overinsur_$(date +\%Y\%m\%d).sql.gz && \
  find /opt/overinsur/backup/ -name "overinsur_*.sql.gz" -mtime +7 -delete
```

### 5.3 重建流程（schema 演进）

schema 变更一律从**运行中的本地开发库导出 canonical schema**，而非手写 SQL 文件：

```bash
# Step 1: 本地导出
docker exec OVERINSURDATA pg_dump -U overinsur -d overinsur_db \
  --schema-only --no-owner --no-privileges > local_schema.sql

# Step 2: 云端重建
cd /opt/overinsur && docker compose --env-file .env down
docker volume rm overinsur_overinsur-pg-data
docker compose --env-file .env up -d overinsur-pg
docker cp local_schema.sql overinsur-pg:/tmp/local_schema.sql
docker exec overinsur-pg psql -U overinsur -d overinsur_db -f /tmp/local_schema.sql

# Step 3: 重新 seed admin（admin 密码不变）
docker cp 06-seed-admin.sql overinsur-pg:/tmp/
docker exec overinsur-pg psql -U overinsur -d overinsur_db -f /tmp/06-seed-admin.sql

# Step 4: 重启 API
docker compose --env-file .env up -d
```

## 六、踩坑记录（重要）

| # | 教训 | 修复 |
|---|---|---|
| 1 | **手写 init SQL 文件不完整**——6 个 init SQL 只覆盖 26 张表，实际后端 SQL 查询引用 39+ 张表 | 放弃手写文件，改用本地 PG `pg_dump --schema-only` 导出 canonical schema |
| 2 | **从 Drizzle schema 生成 DDL 不完整**——11 张表（产品域/财务域）无 Drizzle 定义，只在开发过程中手动建表后自然演进 | schema 始终从运行中数据库导出，而非从 Drizzle 定义或手写文件 |
| 3 | **15 张表 `deleted` 列缺失或默认值不一致** | pg_dump 导出的 schema 自动包含正确默认值 |
| 4 | **云端 DB 密码与本地不一致**——本地 overinsur123 vs 云端随机强密码，排查连接问题时走了弯路 | 生产密码仅存 /opt/overinsur/.env，本地用固定 overinsur123，**两端账号/密码完全分离** |
| 5 | **云端挂载目录权限**——uploads 目录 root 创建，容器内 nestjs 用户无法写入 | `chmod 777 /opt/overinsur/data/uploads/`；长期方案：容器内用户 uid 与宿主机目录 owner uid 对齐 |
| 6 | **ovwr_auth_permission 表从未定义**——seed 脚本 INSERT INTO 不存在的表 | 清理死 seed 脚本；权限走 auth_permission（无前缀） |
