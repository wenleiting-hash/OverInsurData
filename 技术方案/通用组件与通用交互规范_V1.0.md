## 一、目的与基本原则

本规范把已在多个模块反复出现、经业务验证的页面结构与交互方式固化为**项目唯一标准**，目标是：

1. **同一交互只有一种形态**。同类确认/同类列表/同类操作在全系统外观与行为一致（例如"停用保司"与"终止合作"必须是同款居中对话框；"删除"必须弹确认框），禁止同一交互出现两种实现。
2. **视觉只从令牌与全局 class 取值**。颜色、圆角、间距优先使用第三章令牌和 `.btn-primary`/`.card`/`.input-glass`/`.badge-*` 等全局类；新增内联样式只能引用令牌中已有的色值，不得自创色号。
3. **所有可见文案走 i18n**。禁止在组件中硬编码中文（或英文）；新增键必须 zh-CN / en-US 同步。
4. **能复用不新造**。新功能先查第四章"通用原语清单"与第十三章"待沉淀组件"；确认类弹窗以 [DisableModal.tsx](file:///e:/WorkProject/OverInsurData/insurance-platform/apps/web-carrier-admin/src/components/DisableModal.tsx) 为骨架，列表页以 [ProductList.tsx](file:///e:/WorkProject/OverInsurData/insurance-platform/apps/web-carrier-admin/src/views/ProductList.tsx) 为骨架。
5. **危险操作必须二次确认**。删除、停用、终止、下架、批量写操作一律先弹居中确认框，数据变更只在"确认"回调内执行；取消不产生任何写入。

## 四、数据列表页标准（核心）

**参考实现：[ProductList.tsx](file:///e:/WorkProject/OverInsurData/insurance-platform/apps/web-carrier-admin/src/views/ProductList.tsx)**。任何"实体管理/列表"页面（保司、产品、合作、渠道、用户、审计、合规清单……）都由以下 6 段构成，顺序固定：

```
页头（标题+计数+主操作按钮）
筛选条（搜索框 + 筛选下拉 + [清空筛选条件]）
批量操作条（仅选中时出现）
表格卡片（data-table：复选列 / 冻结首列 / 业务列 / 冻结操作列）
分页栏（总数 + 每页条数 + 翻页）
浮层（更多菜单 / 对话框 / 抽屉 / Toast，全部 createPortal 到 body）
```

### 4.1 页头

- 左侧：H1 标题 20px/700 `#181C23`；下方 13px 灰色计数摘要（如"共 N 条 · M 条结果"，走 i18n 插值）。
- 右侧动作区：次要动作（导出等）用 `.btn-secondary`，主新建动作用 `.btn-primary` + `Plus` 图标；按"次要在左、主操作在右"排列。

### 4.2 搜索与筛选区（含"清空筛选条件"）

- 容器：`.card`，padding `14px 18px`，与表格间距 14px；内部 `flex` + `gap:12` + `flex-wrap`。
- **搜索框**：最左、`flex:1 min-width:180~200`；`Search` 14px 灰色图标绝对定位左侧（left:10），输入框 `.input-glass` + `padding-left:30`。
- **筛选项**：`.input-glass` 原生 `<select>`，首个 option 为"全部 XX"；筛选项数量按业务需要。
- **任一筛选条件变化（含搜索输入）必须把页码重置为 1**。
- **清空筛选条件按钮（必备，不得缺失）**：
  - 仅当存在任一非默认条件时出现；
  - 位置：筛选项末尾；
  - 样式：`.btn-ghost`，12.5px，文字色 `#BA1A1A`，前置 `XCircle` 13px 图标；
  - 行为：一键还原全部条件为默认值并回到第 1 页；
  - 文案：中文统一 **"清空筛选条件"**、英文 **"Clear filters"**，统一使用 `common` 命名空间键 `common:filters.clear`（见第十章）。
- 搜索默认 onChange 即时过滤（前端数据）或经防抖进入请求参数（后端数据）；不提供单独"搜索"按钮。

### 4.3 选择列与批量操作条

- 表格首列为复选框，宽 40px，sticky left:0，表头/单元格点击区域不触发行跳转（`stopPropagation`）。
- **表头全选**：
  - 通用列表：选中/取消当前页全部行；
  - 存在"仅部分行可操作"的列表（如合作管理仅洽谈中/待签约可删）：不可操作行复选框 `disabled` 并配 `title` 说明，表头全选只选当前页可操作行，当前页无可操作行时表头复选框置灰。
- 选中后在筛选条与表格之间出现批量操作条：
  - 容器 `.glass-light`，圆角 10，padding `10px 16px`；
  - 起始文案："已选 N 项"（蓝色 `#0058BC` 13px/500）；
  - 批量动作按钮：`.btn-ghost` 12.5px，破坏性动作文字红色 + 对应图标（`Trash2`/`XCircle`）；
  - 右端 `ml-auto`："取消选择"（清空选中集）。
- **批量写操作必须走批量确认对话框**（6.4），禁止直接执行；服务端逐条校验并返回成功/跳过数量，前端 toast 明示"已删除 N 条，M 条已跳过"。
- 批量端点契约：`POST/DELETE .../batch`，body `{ ids: string[] }`（axios DELETE 带 body 用 `{ data: { ids } }`）；响应 `{ deleted|updated: number, skipped: number }`；空数组返回 400；逐条写审计日志。

### 4.4 数据表格

- 外层卡片：`.card` + `padding:0; overflow:hidden`；滚动容器 `overflow-x:auto`（class `.data-table-scroll`）。
- 使用 `.data-table`；表头浅紫底 `rgba(236,237,249,0.5)`（sticky 单元格底色用不透明 `#FCFDFF`/`rgba(236,237,249,0.99)` 防止穿透）。
- **冻结列**：首业务列 sticky left（复选框 40px 之后 left:40/50），操作列 sticky right:0，配方向性投影（左列 `box-shadow:3px 0 8px -2px rgba(0,22,80,0.08)`，右列负值）。
- 行 hover：`rgba(0,88,188,0.03)`（已在 `.data-table` 内置 sticky 单元格 hover 同步）。
- 行点击 = 进入详情（整行可点）；行内按钮/复选框/链接必须 `e.stopPropagation()`，避免误跳转。
- 列不换行；金额用 `font-data`（JetBrains Mono）；状态用 `StatusBadge`/`.badge-*`，可前置 `.orb` 圆点。
- 可排序列表头点击切换 asc/desc，右侧 `ChevronUp/ChevronDown` 12px（非激活 opacity .3）。

### 4.5 操作列：查看 / 编辑 / 更多（统一）

列宽 140~150px，sticky right:0。三个元素从左到右固定为：

| 顺序 | 形态 | 图标 | title（hover 提示，走 i18n） | 行为 |
|---|---|---|---|---|
| 1 查看 | `.btn-ghost` 图标按钮 padding 5 | `Eye` 14 | "查看" / "View" | 进详情页（与点行等价） |
| 2 编辑 | `.btn-ghost` 图标按钮 padding 5 | `Edit2` 14 | 可用："编辑"；禁用：说明原因（如"履行中/已终止的合作不可编辑"） | 可用→打开编辑抽屉/编辑页；**不可编辑时按钮保留可见但置灰**：`opacity:.35` + `disabled` + 原因 title |
| 3 更多 | **文字按钮**（非图标） | 无 | — | 蓝色 12.5px/500 文字 **"更多" / "More"**（不允许用 `MoreHorizontal` 图标或"更多操作"等其他文案），点击展开下拉菜单 |

**"更多"下拉菜单规范：**

1. 用 `createPortal`/fixed 定位挂到 `body`（表格有 overflow 裁剪，不能用绝对定位放在单元格内）；锚点为按钮 `getBoundingClientRect()`（x = rect.right - 菜单宽，y = rect.bottom + 4）。
2. 容器：`position:fixed; zIndex:100; min-width:140; background:#fff; border-radius:10; border:0.5px solid rgba(193,198,215,.4); box-shadow:0 8px 24px rgba(0,22,80,.13),0 1px 3px rgba(0,22,80,.08); padding:5px 0`。
3. 菜单项：整行 button（padding `9px 14px`、13px、左图标 14px + 文案）；hover 底 `rgba(246,248,255,.8)`；**菜单项按当前行状态动态生成**——状态机不允许的动作为禁用项（opacity .4 + `disabled` + `not-allowed`）；破坏性动作（删除、停用、终止）文案红色并配红色图标。
4. 关闭时机：选择一项后关闭、点击菜单外关闭（document mousedown 监听 + ref 判断）、再次点击"更多"切换关闭、Esc 关闭、滚动/翻页时关闭。
5. 菜单项与后端状态机保持同一套常量映射（合作管理参考 `COOP_MENU_ACTIONS`），禁止前后端各写一份。

### 4.6 分页标准

**每页条数选项统一为：`10 / 20 / 50 / 100 / 200 / 500`，默认 10。** 常量统一定义为：

```ts
// 建议沉淀位置：src/components/ui/pagination.ts（见第十三章）
export const PAGE_SIZE_OPTIONS = [10, 20, 50, 100, 200, 500] as const
export const DEFAULT_PAGE_SIZE = 10
```

- 布局：表格卡片内底部，padding `12px 18px`，顶部 `0.5px solid rgba(193,198,215,.4)`，左右两端对齐。
- 左侧：总数文案 + 条数选择。
  - 总数："共 N 条"；服务端分页可扩展"共 N 条 · 第 X / Y 页"。
  - 条数选择：`.input-glass` 小尺寸（12px），选项文案"N 条/页"（en："N / page"），用 i18n 插值 `{size}`，**禁止硬编码 option 文本**。
  - 切换条数立即生效并回到第 1 页。
- 右侧翻页控件（统一形态）：
  - `«`（首页）、`‹`（上一页）、数字页码（最多显示 5 个，当前页居中窗口：`Math.max(1, Math.min(page-2, totalPages-4))`）、`›`（下一页）、`»`（末页）；
  - 全部用 `.btn-ghost` 小尺寸（`5px 10px`）；当前页：底色 `rgba(0,88,188,.10)`、文字 `#0058BC`、600；边界按钮 `disabled`；
  - 数据量大时（总页数 > 50）可在右侧追加"页码输入框（仅数字、回车跳转）+ 跳转按钮"，作为数字翻页的补充（合作管理样式可沿用），但默认形态必须先保留 `« ‹ 数字 › »`。
- 前端分页：`list.slice((page-1)*size, page*size)`，配合筛选条件变化重置页码；后端分页：请求参数 `page/size`，响应 `PaginatedResponse<T>`（`{data/list, total, page, ...}`），用 TanStack Query 的 `placeholderData: prev => prev` 保持翻页不闪。
- 无数据时：隐藏翻页控件，表格体内显示 `EmptyState`。

### 4.7 加载 / 空 / 错误三态

| 状态 | 标准组件 | 出现位置 |
|---|---|---|
| 首次加载 | `PageLoading`（inline）或骨架表 | 表格卡片内容区 |
| 无数据（筛选无结果/尚未创建） | `EmptyState`（图标+标题+描述，可带"新建/清空筛选"动作按钮） | 表格体 |
| 请求失败 | `PageError`（错误信息 + 重试） | 表格卡片内容区 |

禁止用裸文本 "Loading..." / "暂无数据" 替代上述组件。

### 5.2 两种业务类型

1. **表单型确认**（停用/启用、终止合作）：头部 + 影响范围预览（橙色警示盒：`AlertTriangle` + 关键指标网格）+ 原因单选项（卡片式 radio：选中蓝/红浅底 + 同色描边）+ 备注 textarea + 生效方式（立即/定时，定时出现原生 `date`）+ "我已知悉…"勾选；原因与勾选未完成时确认按钮禁用。参考 [TerminatePanel.tsx](file:///e:/WorkProject/OverInsurData/insurance-platform/apps/web-carrier-admin/src/views/cooperation/components/TerminatePanel.tsx)。
2. **简单确认**（删除）：红色头部图标（`AlertTriangle`/`Trash2`）+ 一句话影响说明 + （批量时）对象列表（超过 20 条折叠为"等 N 项"）+ 取消/确认删除。参考 [CooperationDeleteDialog.tsx](file:///e:/WorkProject/OverInsurData/insurance-platform/apps/web-carrier-admin/src/views/cooperation/components/CooperationDeleteDialog.tsx) 与 ProductList 批量确认内联弹窗。

### 5.3 结果反馈

- 成功：优先关闭弹窗 + Toast（第八章）；需要强反馈时在弹窗内显示成功态（绿色 `CheckCircle` 44 + 标题 + 返回按钮），不跳转页面。
- 失败：弹窗内显示红色错误条（可关闭）或 Toast；按钮恢复可点，不关闭弹窗。
- 批量结果：全部成功 → "已删除 N 条"；存在跳过 → "已删除 N 条，M 条已跳过"，用信息色（非错误色），因为跳过属于服务端预期保护。

### 5.4 禁止事项

- 禁止用 `window.confirm/alert`；
- 禁止把确认表单做成页面下方的内嵌卡片/面板（V1.0.12 已据此把终止面板改为对话框）；
- 禁止在打开弹窗时执行任何写操作；写请求只能由确认按钮触发。

## 九、国际化（i18n）规范

- 结构：`src/i18n/locales/{zh-CN,en-US}/<namespace>.json`，按业务域分命名空间：`common`（按钮、分页、筛选、批量、对话框通用词）、`insurer`、`product`、`cooperation`、`channel`、`compliance` 等。
- 用法：`const { t } = useTranslation('cooperation')`；跨域取词 `useTranslation(['insurer','common'])`；动态键用 `t(\`view.terminate.reasons.${r}\`)`；插值用 `t('x', { count, date })`，复数通过完整句子区分（不依赖后缀）。
- **零硬编码原则**：按钮、title、placeholder、toast、弹窗、日期标签全部走 t()；唯一例外是调试日志。
- 通用词应下沉到 `common` 后复用（统一行动），首批下沉键建议：
  - `common.actions.view/edit/more/cancel/confirm/delete/save/export/create`
  - `common.filters.searchPlaceholder/all/clear`
  - `common.bulk.selectedCount/batchDelete/cancelSelection`
  - `common.pagination.total/pageSize/page/jump`（"共 {total} 条"、"{size} 条/页"、"第 {page} / {total} 页"、"跳转"）
  - `common.dialog.confirmDelete/deleting/processing`
  - `common.state.*`（如后续跨模块复用状态词）
- **中英键必须 1:1**。提交前用 flatten 脚本比对两个 JSON 的键集合（合作域当前 692/692 即按此校验），缺键不得合入。

## 十、数据层配套约定

- 服务文件：`src/services/<domain>Service.ts`，基于 TanStack Query v5。
- **Query Key 工厂**为唯一键源，禁止手写字符串数组：

```ts
export const xxxKeys = {
  all: ['xxx'] as const,
  list: (params?) => ['xxx', 'list', params] as const,
  detail: (id) => ['xxx', id] as const,
  // 子资源继续层级展开
}
```

- 查询：列表 `staleTime: 30_000` + `placeholderData: prev => prev`；详情 `enabled: !!id`。
- 变更：mutation 成功后 `invalidateQueries({ queryKey: xxxKeys.all })`；乐观更新仅用于明确需要的场景。
- HTTP：`src/lib/user-api-client.ts` 统一 axios 实例与拦截器；分页响应统一 `PaginatedResponse<T>`；错误信息取 `err.response.data.message` 透传。
- 列表请求参数命名：`page`（从 1 开始）、`size`；前端筛选字段与参数同名。
- 批量/危险操作端点：批量 `{ids}` → `{updated|deleted, skipped}`；删除一律软删 + 审计；按钮置灰规则必须有后端状态守卫兜底（前端置灰只是体验，不是安全边界）。
