# 产品功能清单 — 海外保险数字化平台

> **部分内容由豆包生成**
> **文档版本：** V1.0.3
> **目标市场：** 美国（United States）/ 中国（China）双业务国别
> **模块范围：** 保险公司管理（V1.0.2 原样保留）+ 渠道管理（V1.0.3 重组：7 大业务模块 + 2 个独立子模块，共 9 个子模块）
> **语言策略：** en-US（默认）+ zh-CN（可选），与 businessCountry 解耦
> **功能点总数：** 115 个（保司侧 41 项 V1.0.2 原样保留 + 渠道侧 62 项 V1.0.3 重组（含渠道订单 3 项，单列独立子模块） + i18n 12 项 V1.0.2 原样保留）
>
> **V1.0.3 核心调整背景：**
> 1. **渠道管理 7 大模块重组**：原 V1.0.2 渠道管理 10 个子模块（主数据/层级/入驻/授权/佣金方案/佣金结算/绩效/培训/门户/数据分析）重组为 7 大业务模块（档案/合作/授权/培训/合规/结算/政策，共 53 项）+ 2 个独立子模块（渠道订单 3 项 + 渠道数据分析 6 项），共 9 个子模块：① 渠道档案 ② 渠道合作 ③ 渠道授权 ④ 渠道培训 ⑤ 渠道合规 ⑥ 渠道订单（独立，本期建设，从渠道结算拆出单列）⑦ 渠道结算 ⑧ 渠道政策 ⑨ 渠道数据分析（独立）；**渠道入驻与准入、渠道绩效考核、渠道门户 Portal 三个子模块本期移出渠道管理范围**。
> 2. **业务国别分轨（US/CN）**：引入 businessCountry 字段（US/CN），贯穿渠道侧所有主数据与子表；US 业务按美国保险口径（NPN/Appointment/LOB/State/FEIN/Resident State/E&O/W-9/Producer License/CE Course/Contingent Commission/Premium Tax/Stamping Office/1099-MISC/1099-NEC），CN 业务按国内保险口径（统一社会信用代码/法人证件/营业执照/增值税发票）；UI 层按 businessCountry 显示对应字段集，与语言切换（中/英）解耦。
> 3. **渠道业务员 Individual Producer 全字段管理**：本期建设渠道下具体业务员（Individual Producer）档案：NPN、First/Last Name、SSN Last 4、Resident State、License States、License LOA、Appointment 列表（Carrier×State）、CE 学时进度、有效期、状态（Active/Expired/Surrendered/Revoked）；不再以"代理人"笼统命名，明确区分渠道机构与业务员个体。
> 4. **渠道订单本期建设（起点为渠道商上报客户询价）**：V1.0.3 必须建设渠道订单，订单起点从**渠道商上报客户询价（Quote）**开始：渠道商上报客户询价信息（客户/风险明细/保障意向）→ 报价（保司 API 开放前人工报价/费率档案试算登记）→ 客户确认 → 投保申请 → 核保登记 → 保司出单回填保单号 → 与保司账单匹配 → 进入结算对账。订单类型覆盖 Quote/New Business/Renewal/Endorsement/Cancellation/Reinstatement 共 6 种；询价/失效/撤回/拒保订单不进结算，仅 BOUND 后成交订单参与佣金计算；订单状态机覆盖全链路闭环（功能点 12.1 询价订单与报价管理 + 12.2 成交订单管理 + 12.3 订单状态机，单列"十二、渠道订单"独立子模块）。
> 5. **渠道结算独立模块**：财务模块是结算主数据唯一维护入口（合作详情只读+跳转）；资金四段式流转：① 客户向保司投保付款 → ② 保司收保费按协议返点给我司（上游结算，属保司模块） → ③ 我司收到保司返点按合作协议付给渠道（下游结算，属渠道模块） → ④ 渠道收到佣金；保司账单条目 ID 关联但分属不同模块。
> 6. **合规硬联动+白名单豁免**：恢复渠道合规模块（V1.0.2 已移除），口径为"硬联动+白名单豁免"：合规异常 → 自动挂起关联实体（授权/合作/结算）→ 检查白名单（渠道×监测项×豁免期）→ 命中则不挂起仅记录 → 推送整改任务 → 复检通过自动恢复/未通过升级处理；非 V1.0.1 的自动筛查。
> 7. **渠道政策单向发布**：新增渠道政策模块：管理我司下发保险公司政策（Underwriting Guideline / Rate Manual / Product Bulletin / Compliance Bulletin / Carrier Notice）；时效 Permanent/Term（Days/Months/Quarter/Years）；防冲突规则：同一产品同一类型政策有效期不可重叠；不接收渠道上报。
> 8. **6 开关授权+限额继承**：替换原"授权类型"字段为 6 开关：可报价 / 可出单 / 可批改 / 可续保 / 可退保 / 可理赔；限额继承：单笔保费上限、月度/季度累计上限、子渠道限额 ≤ 父渠道限额；前置校验三件套：产品可售州 ∩ 渠道持牌州 ∩ 合作协议有效期 = 可授权范围。
> 9. **业务员 License 联动**：业务员 License 过期 → 自动暂停该业务员所有 Appointment；业务员 CE 未达标 → 触发培训任务 + 暂停新单 Binding；Appointment 状态 Withdrawn/Revoked → 联动挂起渠道授权。
> 10. **Contingent Commission 年度核算**：补齐美国保险或有佣金：Loss Ratio 阈值 → 触发比例、核算周期年度、结算方式；Contingent Commission 年报生成。
> 11. **Premium Tax 代缴配置**：补齐美国保险保费税：州 × 业务类型 Admitted/Surplus → 税率、代收代缴方；Premium Tax 月报按州汇总；1099-MISC/1099-NEC 年报生成。
> 12. **Stamping Office 加签**：Surplus Lines 业务登记 Stamping Office 加签状态（SLGS/Stamping Office 加签结果、加签失败告警）。
> 13. **i18n 扩展**：新增 channel.json 命名空间（zh/en 对称），键命名前缀 ch（避免与现有 coop/fin/ins 冲突）；美国保险专业术语双语对照固定：Producer License/NPN/Appointment/MGA/Surplus Lines/Admitted-Non-Admitted/Premium Tax/CE/Contingent Commission/Bound/Endorsement。
> 14. **业务国别与语言切换解耦**：businessCountry（US/CN）数据层 + 语言（中/英）UI 层独立；US 业务英文用专业保险术语；CN 业务用国内保险口径；双语对称验证：每个视图完成后 zh/en 截图对比 + 0 raw key 泄露 + 0 全角标点泄露到 en。
> 15. **保司管理保持 V1.0.2**：保险公司管理（含保险公司主数据/保险产品/我司与保司合作/Appointment/财务结算/数据分析 6 个子模块）原样保留 V1.0.2 内容，不做 V1.0.3 新口径调整，避免引入风险。
> 16. **V1.0.2 内部计数勘误**：V1.0.2 目录标保司 35/36 个，实际加总 41 个；V1.0.3 按实际 41 个统计。

# 第一部分：保险公司管理模块

> **模块定位（V1.0.2 原样保留）：** 本模块为我方纯内部管理域。上游保险公司无开放 API，全域不设审批流，采用「登记制 + 审计日志」模式：所有业务动作由有权限运营人员直接操作生效，系统记录完整审计日志；涉及外部联动、自动执行、审批的功能降级为登记备查，相关枚举选项保留 UI 但置灰不可选（标注「待开放」）。V1.0.2 移除 6 项合规功能（OFAC 筛查、合规拦截、NIPR 牌照查询、牌照到期提醒、合规规则配置、合规审计报告），仅保留 Appointment 线下登记四件套。
>
> **V1.0.3 注：** 保险公司管理部分（1.1-6.6 共 41 个功能点）原样保留 V1.0.2 内容，不做调整。本章操作级清单与 V1.0.2 一致，仅在文档版本号与统计口径上对齐 V1.0.3（V1.0.2 目录标 35/36 个，实际加总 41 个，V1.0.3 统一按 41 个统计）。

## 一、保险公司主数据管理

### 1.1 保险公司新增

**功能描述：** 创建新的保险公司档案，录入基本信息、监管信息、财务评级等，建立平台与保险公司的合作基础。

| 操作名称 | 操作说明 |
|---|---|
| 填写基本信息 | 录入公司全称、简称、中文译名、成立年份、官网 |
| 填写监管信息 | 录入NAIC编码、公司类型（Admitted/Non-Admitted） |
| 填写总部信息 | 选择总部所在城市、州、大区、分区 |
| 填写财务评级 | 录入AM Best、S&P、Moody's、Fitch评级及评级日期 |
| 填写结算信息 | 配置佣金结算周期（月/季）、账单格式（CSV/Excel）；EDI/API/Manual 选项保留枚举但置灰不可选（待开放） |
| 上传资质文件 | 上传营业执照、监管批文、评级报告等附件 |
| 保存草稿 | 暂存未完成的录入信息，可后续继续编辑 |
| 提交 | 提交保险公司档案 |
| 重置表单 | 清空当前已填写内容 |

### 1.2 保险公司编辑

**功能描述：** 修改已有保险公司的档案信息，支持部分字段更新，所有变更记录审计日志。

| 操作名称 | 操作说明 |
|---|---|
| 编辑基本信息 | 修改公司名称、简称、官网等基础字段 |
| 编辑监管信息 | 修改NAIC编码、公司类型等监管字段 |
| 编辑财务评级 | 更新评级机构评级及评级日期 |
| 编辑结算信息 | 修改结算周期、账单格式等财务配置 |
| 新增/替换附件 | 上传新的资质文件，替换过期文件 |
| 删除附件 | 删除不再需要的附件文件 |
| 保存修改 | 提交修改，系统自动记录变更前后值 |
| 查看变更历史 | 查看该保险公司所有历史修改记录 |
| 字段级变更对比 | 对比某两次修改之间的字段差异 |

### 1.3 保险公司停用/启用

**功能描述：** 控制保险公司的合作状态，停用后不再分配新业务但已有保单和佣金继续正常处理。【V1.0.1 调整】停用/启用无审批环节，由有权限运营人员直接操作生效，全程写入审计日志。

| 操作名称 | 操作说明 |
|---|---|
| 停用保险公司 | 将状态改为"已停用"，停止新业务分配，操作立即生效并记录审计日志 |
| 启用保险公司 | 将状态从"已停用"恢复为"合作中"，操作立即生效并记录审计日志 |
| 填写停用原因 | 停用必须选择原因（业务终止/合规问题/系统迁移等），原因随审计日志留存 |
| 影响范围预览 | 停用前展示受影响的渠道数、产品数、在途保单数 |
| 批量停用 | 勾选多家保险公司批量停用，逐条记录审计日志 |
| 批量启用 | 勾选多家保险公司批量启用，逐条记录审计日志 |
| 操作审计 | 停用/启用操作自动写入审计日志（操作人、时间、原因、前后状态），可追溯 |

### 1.4 保险公司详情查看

**功能描述：** 查看保险公司的完整档案信息及关联业务数据的一站式页面。

| 操作名称 | 操作说明 |
|---|---|
| 查看基本信息 | 展示公司全称、简称、NAIC、总部、成立时间等 |
| 查看财务评级 | 展示各评级机构当前及历史评级 |
| 查看关联产品列表 | 展示该保险公司下所有产品及状态（含可售州只读列，可售州取自产品档案） |
| 关联已有产品 | 【V1.0.14 明确】弹窗仅勾选产品主数据（按名称/代码搜索、批量勾选），不在关联操作中维护可售州、佣金率、生效日期；可售州为产品档案中登记的保司获批州（见 2.7），我司实际销售区域与州级返佣差异由合作关系/合作协议约定（见 3.2/3.3） |
| 查看合作渠道列表 | 展示所有合作渠道及合作状态、业绩 |
| 查看业绩概览 | 展示保费、保单数、增长率等核心指标（赔付率、续保率因上游无数据源，暂不展示） |
| 查看佣金方案 | 展示该保险公司关联的所有佣金方案 |
| 查看资质附件 | 预览和下载所有上传的附件文件 |
| 查看变更历史 | 展示档案信息的所有变更记录 |
| 跳转产品管理 | 点击产品跳转到产品详情页 |
| 跳转渠道详情 | 点击渠道跳转到渠道详情页 |
| 导出详情报告 | 将保险公司详情导出为PDF |

### 1.6 批量导入

**功能描述：** 通过Excel模板批量导入保险公司数据，支持校验和错误反馈。【V1.0.1 调整】导入后状态为"待激活"（原"待审核"），由运营人员手动激活后生效。

| 操作名称 | 操作说明 |
|---|---|
| 下载导入模板 | 下载标准Excel导入模板（含字段说明和示例） |

## 三、我司与保险公司合作管理

> **模块定位说明：** 本模块管理**我司（平台方）与上游保险公司**的合作关系：签约、合同、结算参数、对接人、续约登记、合作协议产品关联。
>
> **模块边界（2026-09-12 业务澄清后修订）：**
> - **上游合作（本模块 3.1–3.7）：** 我司 ↔ 保险公司 —— 合作建立/终止、合同协议、结算参数、对接人、续约登记、合作协议产品关联（关联即生效，无申请审核）。
> - **中间授权（不属于本模块，归入渠道管理域 → 第九章）：** 保险公司授权我司的产品，由我司按渠道进行**产品销售授权、出单权限与限额配置**（原 V1.0.2 第十章内容已重组到第九章渠道授权）。
> - **下游管理（渠道管理模块）：** 我司 ↔ 渠道合作商 —— 档案、层级、合作、授权、培训、合规、结算、政策、数据分析。
>
> 我司作为中间平台，从保险公司获取产品资源和出单权限，再授权给我司发展的渠道合作商使用。**合作记录与渠道授权不做强绑定、不做自动级联**：合作终止不自动收回渠道授权，渠道授权的配置/收回由第九章独立管理。

### 5.2 佣金对账

**功能描述：** 【V1.0.1 调整】将系统基于佣金率试算的应付佣金与保险公司账单逐笔比对，标记差异。期望值来源升级为"佣金率试算 + 导入校正"（依据 5.5 结算比例配置主数据）。【V1.0.14 补充】佣金率支持州维度，逐笔试算按「产品+州 → 产品（全域）→ 险种+州 → 险种（全域）」四级回退匹配，均未配置时采用导入对账单原值。【V1.0.2 明确】完整对账流程为：① 保司导出对账单 → ② 我方导入生成导入批次（5.1）→ ③ 在批次详情中针对该批次按协议佣金率计算我方应得佣金 → ④ 与该批保司账单逐笔对账 → ⑤ 金额一致则批次对账完成 → ⑥ 不一致则标记为异常差异（5.3），跟保司核实后人工处理。对账以**导入批次**为运行单位，结果回写批次与对账行，不修改原始账单数据。

## 十三、渠道结算

> **V1.0.3 重组+扩展：** 合并 V1.0.2 的"佣金方案配置与管理"+"佣金计算与结算"21 个功能点，重定义为"渠道结算"（共 13 个功能点）；渠道订单已拆出单列为 12 渠道订单独立子模块（本期建设）。
>
> **资金四段式流转：** ① 客户向保司投保付款 → ② 保司收保费按协议返点给我司（上游结算，属保司模块） → ③ 我司收到保司返点按合作协议付给渠道（下游结算，属渠道模块） → ④ 渠道收到佣金。
>
> **模块边界：** 保司给我司账单 = 上游对账（属保司模块 5.x）；我司给渠道佣金 = 下游结算（属渠道模块 13.x）；两者通过"保司账单条目 ID"关联但分属不同模块。
